# 公告指引規範

給之後寫公告的人（含 Claude）。**讀公告的是國小四～六年級的同學**，不是老師，也不是工程師。
寫完先自己唸一遍：同學聽得懂嗎？一次看得完嗎？

## 一、公告放哪裡（四個地方，各有各的讀者）

| 地方 | 在哪 | 誰看 | 長度 |
|---|---|---|---|
| 新世界「📢 佈告欄」＋進去跳一次的視窗 | `newworld.js` 的 `NOTICES` | 玩新世界的同學 | 一則公告 3～5 條，每條 1～2 句 |
| 遊戲右下角 `v…` 的版本紀錄 | `index.html` 的 `VERSION_LOG` | 所有同學 | 每個類別 1～4 條，每條 1 句 |
| 電腦教室入口頁右上角小訊息 | pcclass 的 `TYPEHERO_UPDATES` | 還沒進遊戲的同學 | 一則 **20 字以內**，保持 3～5 則 |
| `CHANGELOG.md`、`docs/HANDOFF.md` | 文件 | 接手開發的人 | 可以寫技術細節，**不給學生看** |

前三個是給學生看的，都要照這份規範寫。第四個是給大人看的，不用。

## 二、只寫「現在玩得到」的

- 只寫已經上線、同學現在就能用的功能。預告、施工中、只有搶先體驗的人才有的，**不能寫成「開放了」**。
- 想預告，就寫成預告：「鐵匠鋪快蓋好了，再等一等」，不要寫日期，也不要保證。
- 新世界相關的訊息，只寫「進得去新世界的同學」看得到的內容；入口頁（還沒進去的人也會看到）只寫已經對全班開放的功能。
- 通關密語、序號、學生姓名座號**絕對不寫進公告**。

## 三、怎麼說話

### 1. 先講「你可以做什麼」，再講「改了什麼」

- ✅ 「打完標點符號挑戰，就能進新世界！」
- ❌ 「標點符號挑戰完成後，新世界權限自動開通。」

### 2. 句子短、一句一個意思

- 一句不超過 **25 個字**，一條不超過 **2 句**。
- 不用「，而且，並且，以便，進而」把句子串很長。分成兩句。
- 數字用阿拉伯數字（5 下、3 個），別寫「五」「參」。

### 3. 用同學平常會說的字

照 `docs/GDD-NEWWORLD.md` §2.3 的用詞表，再加上這些：

| 不用 | 改用 |
|---|---|
| 權限、開通、解鎖條件 | 「就能進」「可以用了」 |
| 錯誤、異常、Bug、當機 | 「怪怪的」「卡住了」「壞掉了」（回報時才用「錯誤狀況」） |
| 修復、修正 | 「修好了」 |
| 優化、調整、改版 | 「變得更好玩」「改了一下」；大改才用「改版」 |
| 觸發、執行、操作 | 「按」「點」「做」 |
| 獲得、取得 | 「拿到」「得到」 |
| 完成度、進度 | 「做到哪裡了」 |
| 介面、選單 | 「畫面」「按鈕」 |
| 數值、參數 | 「力氣」「速度」「血量」等實際的東西 |
| 提供、支援 | 「有」「可以」 |
| 請務必、須知 | 「記得」「要」 |
| 死亡 | 倒下 |
| 弱點／抗性 | 怕／不怕 |
| 詞條 | 附加能力（公告裡的稱號可以寫「稱號詞」） |

- 英文縮寫和程式用語（HP、ID、UI、API、localStorage、Firebase）**不要出現**。
- 按鈕、地方的名字用「」框起來，要跟畫面上一模一樣：「📢 佈告欄」「教學大樓」「回報問題」。
- 稱號、道具名稱也用「」：「職業除錯師」。

### 4. 語氣

- 友善、像學長姐在講話，不要像公文，也不要太幼稚。
- 可以用「你」，不要用「您」「各位同學」「請同學們」。
- 不命令、不責備。別寫「禁止」「嚴禁」「不得」；要提醒就寫「記得…喔」。
- 表情符號：每一條最前面放 **1 個**說明這一條在講什麼的圖案（🎫 🏫 🐛 📌 🎒），不要連放好幾個，也不要放在句子中間。
- 驚嘆號：一則公告最多 2 個，不要每句都「！」。

### 5. 壞消息也要講清楚

- 先說「怎麼了」，再說「怎麼辦」，最後給一句安心的話（如果真的有）。
- ✅ 「太快點背包，換裝備教學會卡住。已經修好了，不用再擔心。」
- ❌ 「已修復教學流程之競態條件。」
- 如果同學的東西不見了或需要重做，一定要講「要做什麼」，還有「老師知道了」。

## 四、一則公告的格式（`NOTICES`）

```js
{ id: '2026-11-12', date: '11 月 12 日', title: '新世界改版啦！', items: [
  '🎫 打完「標點符號挑戰」就能進新世界！',
  '📌 第一次進村有介紹，箭頭會先帶你去「教學大樓」。',
  '🐛 回報問題要寫清楚：做了什麼事、出現什麼狀況。'
] }
```

- `id`：日期 `YYYY-MM-DD`，同一天有兩則就加 `-2`。**新公告放陣列最前面**，舊的不要改、不要刪（佈告欄要留著讓同學回頭看）。
- `title`：10 個字以內，講這次最重要的一件事。「新世界改版啦！」「新武器來了」「修好了幾個問題」。
- `items`：**3～5 條**。最重要的放第一條。超過 5 條就拆成兩則公告，不然同學會跳過不看。
- 每條開頭 1 個圖案，後面最好 15～40 個字。
- 進新世界時只會自動跳**最新一則**，而且只跳一次。所以最新那則要自己讀得懂，不要寫「承上次公告」。

## 五、版本紀錄（`VERSION_LOG`）的寫法

- 分「新增 `added`／改了 `changed`／修好了 `fixed`」，沒有就留空陣列。
- 一條一句，跟公告同樣的用詞。不寫程式用語（函式名稱、欄位名稱）。
- 寫「同學看得到的變化」，不寫「我們改了哪些程式」。
- ✅ 「新世界多了「📢 佈告欄」，想再看改版說明就按它。」
- ❌ 「新增 NOTICES 與 seenNotice 欄位，進場時顯示一次。」

## 六、入口頁小訊息（`TYPEHERO_UPDATES`）

- 20 字以內，一則只講一件事，開頭 `icon` 用單一表情。
- 規則見 `CLAUDE.md` 的發版清單；這裡補充：**同學還沒進遊戲就會看到**，所以只寫全班都玩得到的。
- ✅ 「標點練習變短了！看完再練，還要打怪」
- ❌ 「新世界教學大樓更新」（沒進新世界的人看不懂，也玩不到）

## 七、寫完檢查（每一條都要打勾）

- [ ] 這個功能現在真的玩得到嗎？（不是預告、不是施工中）
- [ ] 四年級的同學唸一遍，每個字都懂嗎？有沒有「權限、修復、觸發、介面」這類大人字？
- [ ] 一句有沒有超過 25 個字？一條有沒有超過 2 句？
- [ ] 按鈕、地方、稱號的名字，跟畫面上一模一樣，而且有用「」框起來嗎？
- [ ] 先講「你可以做什麼」了嗎？壞消息有講「怎麼辦」嗎？
- [ ] 有沒有不小心寫到密語、序號、同學的名字或座號？
- [ ] 有沒有英文縮寫、程式用語？
- [ ] 表情符號是不是每條 1 個、放在最前面？驚嘆號有沒有太多？
- [ ] 新公告有放在陣列最前面、舊的沒動嗎？
- [ ] 公告條數在 3～5 條之間嗎？

## 八、好壞對照（照著改）

| ❌ 不好 | ✅ 好 |
|---|---|
| 新增佈告欄功能，提供改版資訊查詢。 | 📢 新增「佈告欄」，想再看改版說明就按它。 |
| 優化教學大樓之互動流程，並新增戰鬥環節。 | 🏫 教學大樓每堂課最後，要把稻草魔物打倒（打 5 下）。 |
| 修復背包連點導致教學中斷之異常。 | 🎒 修好了：太快點背包，換裝備教學會卡住。 |
| 回報問題須詳述操作步驟及錯誤訊息，否則不予採計。 | 🐛 回報問題要寫清楚：你做了什麼事、出現什麼怪狀況。 |
| 請各位同學務必於完成標點符號挑戰後再行進入。 | 🎫 打完「標點符號挑戰」，就能進新世界！ |
