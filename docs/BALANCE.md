# 數值平衡總表（BALANCE）

> **這份文件是血量、傷害、經驗、等級、難度層級的唯一規格書。**
> 程式裡只有一個 `BALANCE` 物件（在 `index.html`，搜 `const BALANCE`），
> 數字只能從這裡改；改完請回來更新這份文件與 `CHANGELOG.md`。
>
> 版本：`BALANCE.ver = 3`（v3 取消動態難度，改為三層級固定曲線）
>
> **v3 的主要改動**：動態難度（DDA）移除，改成新手教學量一次、
> 分成三個難度層級各走一條**線性**曲線（§7）。這樣做的唯一理由是
> **讓局外成長真的看得出效果**——見 [`META-GROWTH.md`](META-GROWTH.md)。

## 0. 這些數字是怎麼來的（校準基礎）

全部取自 **2026-09-10 的 Firestore `mg_scores` 實際紀錄（139 筆、17 個班）**，
不是猜的。關鍵事實：

| 項目 | 實測 |
|---|---|
| 每場時間（`mg_config.duration`） | **120 秒**（不是 README 寫的 600） |
| 老師設的難度係數 | **0.3×**（被迫調到最低才勉強能玩） |
| 每分鐘正確字數 `bestWpm` | p10=3　p25=6　**中位 10**　p75=14　p90=19　最高 45 |
| 單場最多擊倒 `bestKills` | **0 隻：48 人（35%）**、1 隻：48 人、2 隻：23 人、3 隻：11 人、4+：9 人 |
| 歷史最高傷害 `bestDamage` | p25=43　中位 95　p75=221　p90=437 |
| 分年級中位 wpm | 四年級 7、五年級 10、六年級 13 |

### 診斷出的三個病灶

1. **一堂課只有 2 分鐘、中位學生只打得出 ~10 次攻擊**（20 個正確字）。
   原本第一隻史萊姆 100 血、每下 6.6 傷害 → **要 15 下**，所以 35% 的學生
   一次都沒推倒過任何怪，整場只看到同一隻史萊姆的血條動一點點。
   這就是「學生一直卡在同一隻」的根因。
2. **老師只能用難度係數 0.3 全班一起調**，快的學生同時被調到無聊。
   → v2 改成每個人一條 DDA（動態難度）；**v3 改成三個難度層級**（§7），
   理由見 §7.1。
3. **階級徽章看總傷害**，但總傷害同時受「打字速度 × 品質倍率 × 場次長度」影響，
   2 分鐘場次下 53% 的學生永遠停在見習生（實測分布見下表）。
   → 改成看「每分鐘正確字數」換算的戰績分。

| 舊階級（看 bestDamage） | 人數 | 比例 |
|---|---|---|
| 見習生 | 73 | **53%** |
| 冒險者 | 33 | 24% |
| 銅級 | 18 | 13% |
| 銀級 | 7 | 5% |
| 金級 | 6 | 4% |
| 傳說 | 2 | 1% |

## 1. 心流理論怎麼落到數字上

Csikszentmihalyi 的心流要 **挑戰≈能力**、**目標明確**、**回饋即時**。
對應到這個遊戲：

| 心流條件 | 本版做法 | 對應數字 |
|---|---|---|
| 挑戰≈能力 | 血量不是固定值，而是**由「打倒一隻要幾個正確字」(CTK) 反推** | `hp.ctk*` |
| 挑戰≈能力（個人化） | 新手教學量一次手速，分成三個難度層級，各走一條固定曲線 | `tier.*`（§7） |
| 第一次就不卡 | 層級在教學當場就決定，第一場正式戰就是對的難度 | §7.3 |
| 目標明確 | 經驗條、等級、怪物等級、區域進度都顯示在畫面上 | 見 §5 §6 |
| 回饋即時 | 每下都有傷害數字；連擊另外跳「追加傷害」 | 見 §4 |
| 難度遞增但不斷崖 | CTK 依層級線性成長，等級攻擊力同步成長，**有效下數從 1.0～2.7 平滑爬到 2.3～6.4** | 見 §3 |
| 避免無聊（強者） | 等級無上限，怪物隨等級換區、每區末有王級 | 見 §6 |
| **成長看得見** | 難度固定，不會反過來追著玩家跑，天賦與等級的效果直接顯示在「打得動多深」 | §7.1、[`META-GROWTH.md`](META-GROWTH.md) |
| 避免焦慮（弱者） | 初階第一隻只要 1 個正確詞（CTK 2.0），不需要偷偷放水 | `tier.A`（§3） |

**核心設計句**：*血量不是「怪有多硬」，而是「老師希望這個孩子打幾個字才有成就感」。*

## 2. 傷害公式

```
perCharDmg(quality, weapon) = quality.mult × weaponMult(weapon) × dmgScale
hitDamage = 正確字數 × perCharDmg × atk(LV) × comboMult ( + 法杖標點加成 )
atk(LV)   = 1 + atkPerLv × (LV - 1)
```

| 參數 | 值 | 說明 |
|---|---|---|
| `dmgScale` | **8** | 全域放大。讓「普通」一下打出 ~53 點而不是 6.6 點，數字有打擊感 |
| `weapon.staff` | 2.2 | 法杖 |
| `weapon.dagger` | 2.0 | 匕首 |
| `weapon.bow` | 0.6 + 1.2×正確率 | 弓箭（全對＝1.8） |
| `quality.normal.mult` | 1.5 | |
| `quality.fine.mult` | 2.0 | |
| `quality.epic.mult` | 2.9 | |
| `quality.legend.mult` | 4.2 | |
| `atkPerLv` | **0.04** | 每升一級 +4% 傷害（局內成長感） |
| `staffPunct` | 3 × `dmgScale` = **24** | 法杖每個正確標點 |
| `chantMult` | 3 | 詠唱全對 |
| `sharpMult` | 2 | 神射手模式 |
| `flurry` | min 0.9 / max 3.2 / slope 3.4 | 連環斬（照舊） |

**每下傷害實際值（普通品質・法杖・無連擊）**：LV1 = 53、LV6 = 63、LV12 = 76。

> ⚠ 舊紀錄的 `damage` 是舊比例（中位 95），新版同一位學生會打出 ~700。
> 兩者**不可比**。所以 `bestDamage` 只保留給「自己跟自己比」，
> 階級徽章改看 §8 的戰績分（跨版本可比）。

## 3. 血量公式（重點）

血量**不寫死**，由「打倒這一隻需要幾個正確字」反推：

```
CTK(LV) = 層級.ctk0 + 層級.slope × (LV - 1)          ← 線性，沒有動態難度
lenAdj(quality) = (quality.chars / 2) ^ lenPow
HP(LV, quality) = quality.mult × weaponRef × dmgScale × CTK(LV) × lenAdj × 老師難度
                  × (菁英 1.35 / 王級 1.7)
```

`層級` 是學生的難度層級（初階／中階／高階），新手教學量出來之後**就固定下來**，
不會每場變動——見 §7。

| 參數 | 值 | 說明 |
|---|---|---|
| `tier.A.ctk0` / `slope` | **2.0 / 0.30** | 初階：第一隻 1 個正確詞就倒 |
| `tier.B.ctk0` / `slope` | **4.0 / 0.52** | 中階：第一隻 2 下（使用者當初指定的手感，維持不變） |
| `tier.C.ctk0` / `slope` | **6.0 / 0.85** | 高階：第一隻 2.7 下，怪物有份量 |
| `hp.lenPow` | 0.5 | 長題補正，見下方說明 |
| `weaponRef` | **2.0** | 血量用「參考武器倍率」而不是實際武器，**所以武器選擇還是有差**（法杖快 10%、弓箭慢一點但有神射手） |
| `quality.*.chars` | 普通/精良 2.0、史詩 3.5、傳奇 8.0 | 各池平均字數 |

### 為什麼從指數曲線改成線性

舊版是 `ctk0 + (ctkMax-ctk0)(1-e^(-(LV-1)/tau))`——**會飽和**，
LV20 之後幾乎不再變難（CTK 從 12.8 爬到 15.4 只多了 2.6）。
搭配動態難度是合理的（難度由 DDA 負責），但**動態難度取消之後，
飽和曲線會讓後期完全沒有壓力**，局外成長也就沒有「往前推」的舞台。

線性的代價要講清楚：**前期比舊版鬆、後期比舊版緊**。
舊版 LV3 就要 2.6 下，線性版 LV3 只要 2.1 下，要到 LV8～10 才達到 3 下。
換來的是後期（LV20+）真的會越來越硬，而不是停在 3.3 下不動。

### 為什麼血量要乘上品質倍率

因為公式的單位是「正確字數」。乘回 `quality.mult` 之後，**品質倍率在血量裡被抵銷**，
結果是：**選什麼品質，打倒一隻要的「字數」都差不多**。
品質改成決定三件事 —— 經驗值權重、班級總傷害貢獻、戰績分加成（§8）。
這是刻意的：**難度是「進度快慢」，不是「怪變不變軟」**，
孩子才不會為了多殺幾隻而一直賴在普通。

### lenPow（長題補正）

傳奇一題 8 個字，若完全按字數算，一題就能掃掉兩三隻怪、血條毫無張力。
所以血量再乘 `(字數/2)^0.5`：普通 1.00、史詩 1.32、傳奇 2.00。
結果傳奇每隻約 1.4～1.6 下，擊倒數變少但每下很重 —— 這是傳奇該有的手感。

### CTK 表（三個層級，老師難度 1.0）

打倒一隻要幾個正確字：

| LV | 初階 | 中階 | 高階 |
|---|---|---|---|
| 1 | 2.0 | **4.0** | 6.0 |
| 3 | 2.6 | 5.0 | 7.7 |
| 5 | 3.2 | 6.1 | 9.4 |
| 10 | 4.7 | 8.7 | 13.6 |
| 15 | 6.2 | 11.3 | 17.9 |
| 20 | 7.7 | 13.9 | 22.1 |
| 30 | 10.7 | 19.1 | 30.6 |

### 普通品質「要幾下」（含等級攻擊力成長）

| LV | 初階 | 中階 | 高階 |
|---|---|---|---|
| 1 | **1.0** | **1.8** | **2.7** |
| 3 | 1.2 | 2.1 | 3.2 |
| 5 | 1.3 | 2.4 | 3.7 |
| 10 | 1.6 | 2.9 | 4.6 |
| 20 | 2.0 | 3.6 | 5.7 |
| 30 | 2.3 | 4.0 | 6.4 |

初階第一隻**一個正確詞就倒**——這是給班上最後段那幾個孩子的地板，
他們一場只打得出 4～8 個正確字，再高就是整場 0 擊倒。
高階 LV30 要 6.4 下，那是給 wpm 30 的孩子的天花板。

## 4. 連擊加成（追加傷害）

```
comboMult = 1 + min(cap, step × max(0, combo - from + 1))
```

| 參數 | 值 |
|---|---|
| `combo.from` | 2（第 2 連擊開始加） |
| `combo.step` | **0.06**（每連擊 +6%） |
| `combo.cap` | **0.90**（最多 +90%，約 16 連擊封頂） |
| `combo.expBonusEvery` / `combo.expBonus` | 每 5 連擊 +10 經驗（§5 調降過，經驗主要來源是擊倒） |

**顯示規格**：傷害數字照舊（白／金），**另外**在它下方跳一個較小的金色
`追加 +N`（N = hitDamage − 無連擊的 hitDamage），並在連擊標籤顯示
`7 連擊　+36%`。連擊歸零時標籤閃紅一下再消失。

全對才累計連擊（沿用現行 `res.perfect`），`Esc` 跳過歸零。
**血量公式不含連擊**，所以連擊是真正的加速器，手感最直接。

**連擊標籤的位置**：試過兩種絕對定位（左上角、右上角）都在實測截圖裡
撞到別的東西——矮螢幕（常見的教室筆電）下，第一人稱武器（左側，往上長）
跟 `#hud-right`（右側正確率／每分鐘字，往上長）都會頂到舞台頂端，
絕對定位疊在舞台上不管放哪個角落都可能被撞到。**最後把連擊標籤整個
搬出舞台，變成 `#topbar`（頁首那排）裡的一顆 chip**，正常排版流不會
跟任何絕對定位的東西衝突，這樣才是真的解決問題，不是換個角落繼續猜。
連擊標籤平常隱藏（`.hidden`），連擊 ≥2 才出現在武器／品質 chip 跟
傷害／時間中間，`justify-content:space-between` 讓它自動置中。

**第一人稱武器的顯示方式整個改掉了**：舊版故意讓武器「下半截被螢幕切掉」
（Minecraft 式第一人稱），矮螢幕下這個設計直接失控——可見的那一截
還是會頂到舞台頂端，杖頭／箭羽被切掉，看起來像斷掉的怪東西。
改成**整把武器永遠完整顯示、貼齊舞台下緣**，`fitViewmodel()` 每次
開戰／換武器／改視窗大小都重新量一次舞台跟武器圖的實際高度，超過舞台
高度的 62%（`VM_MAX_STAGE_FRAC`）就用 `transform:scale()` 縮小、
從底部往上收（`transform-origin:50% 100%`），握把貼地的位置不會跑掉，
不管螢幕多矮，武器整把都在畫面裡。傷害數字（含「追加 +N」）的水平落點
也順便從 38～62% 移到偏右的 48～78%。

**水平位置試過置中，實測會疊在怪獸身上，已經改回靠左**：曾經把武器
從固定 `left:34px` 改成 `left:50%`置中，理由是第一人稱視角置中比較
自然；但怪獸圖本身也是水平置中的（`#monster-slot` 用
`justify-content:center`），矮螢幕下兩個擠在同一塊區域，會直接疊成一
片看不出誰是誰——這是連上瀏覽器截圖後才抓到的，單靠算座標沒發現。
最後定案：**武器維持靠左（`left:6%`，跟怪獸的水平範圍錯開），
垂直方向的「整把完整顯示」照樣保留**，兩個東西才會同時看得清楚。
這也是為什麼匕首揮砍的支點可以簡化成固定的 `50% 100%`（見上面
「連擊加成」一節的匕首備註已經沒有動態量測支點的邏輯了）——底部
既然貼齊舞台下緣，握把位置就是固定的，不用再每次量。

**怪獸圖也有一樣的問題，一併修了**：`#monster-slot` 原本
`min-height:150px`，矮螢幕（尤其普通品質多長一排注音鍵盤）下這個下限
會逼 flexbox 撐出比舞台實際能給的還高的空間，圖案就溢出舞台底部，
跟弓箭的爆擊條疊在一起。降到 `min-height:60px` 當安全下限，
真正的縮放交給新增的 `fitMonsterArt()`（跟 `fitViewmodel()` 同一套
做法，套在 `#monster-slot` 這個外層，`#monster-art` 自己的受擊／死亡
動畫才不會被打斷），目標抓 slot 高度的九成（留一點緣，不是頂滿）。
**呼叫順序也很關鍵**：`fitMonsterArt()` 一定要排在 `paintZhuyinPad()`
（決定普通品質要不要長出鍵盤）之後才能量到正確的可用高度，不然量到
的是鍵盤出現前、舞台還沒被擠壓的尺寸，算出來的縮放是錯的（`startBattle()`
裡 `drawMonster()` 因此被移到 `paintZhuyinPad()` 後面）。兩個 fit
函式也都加了 `requestAnimationFrame` 保險：剛切畫面那一刻版面可能還沒
完全定案，下一帧再修一次縮放，避免量到還沒 settle 的過渡尺寸。

## 5. 經驗與等級（局內，每場從 LV1 重來）

```
need(LV → LV+1) = needBase + needStep × (LV-1) + needQuad × (LV-1)²
                = 40 + 16 × (LV-1) + 1.2 × (LV-1)²
```

**設計原則：打字只給「一點點」經驗，擊倒才是經驗的主要來源。**
第一版把 `perChar` 訂得太高（一下全對 35 點，幾乎跟殺一隻怪的 38 點一樣），
結果變成「殺不殺怪都無所謂，反正打字就會一路升級」，違背了「血量→CTK→
擊倒感」整套設計的初衷。改成這樣之後，普通品質一下全對只有 **7 點**，
擊倒一隻 LV1 怪卻有 **29 點**——四倍差距，殺怪的份量感拉出來了。

`need(LV)` 多加一個二次項 `needQuad`：早期（LV1-10）幾乎跟原本的線性成長
一樣，但 LV15 以後明顯變陡，跟血量曲線（CTK，見 §3）在後期一起變硬互相
呼應，避免打字快的學生整場不停升級、數字看起來卻沒有真實的「越來越難」。

| 來源 | 經驗 |
|---|---|
| 每個正確字 | `2 × quality.expW` |
| 整題全對 | +3 |
| 擊倒一隻 | `22 + 7 × 怪物等級`（菁英 ×2、王級 ×3） |
| 每 5 連擊 | +10 |

`quality.expW`：普通 **1.00**、精良 **1.33**、史詩 **1.93**、傳奇 **2.80**
（＝`mult / 1.5`）。**這仍然是高品質唯一的硬獎勵**：同樣速度，傳奇升級
快一倍以上——但因為打字本身的權重已經調低，這個獎勵不會蓋過「殺怪為主」
的主軸。

| LV | 升級需求 | 累計 |
|---|---|---|
| 1→2 | 40 | 40 |
| 2→3 | 57 | 97 |
| 3→4 | 77 | 174 |
| 4→5 | 99 | 273 |
| 5→6 | 123 | 396 |
| 8→9 | 211 | 936 |
| 10→11 | 281 | 1,462 |
| 15→16 | 499 | 2,322 |
| 20→21 | 777 | 3,758 |
| 25→26 | 1,115 | 4,874 |

**升級效果**：攻擊力 +4%、跳「LV 7！攻擊力 +4%」橫幅、經驗條歸零繼續。
**沒有血量／復活概念**（學生不會死），一場的盡頭是時間。

### 模擬結果：v1 → v2 經驗曲線對照（2 分鐘・普通・法杖，25 次平均）

> 這張表是 v2 當時的紀錄（那時還有 DDA），留著看經驗曲線的改動效果。
> 難度本身的最新數字請看 §11。

| wpm | 改版前擊倒 | 改版前到達LV | 改版後擊倒 | 改版後到達LV |
|---|---|---|---|---|
| 10（中位） | 5.5 | 9.4 | 5.9 | **5.9** |
| 19 | 6.2 | 10.8 | 7.1 | **6.9** |
| 45（極快） | 15.3 | 20.7 | 17.6 | **12.7** |

擊倒數幾乎沒變（當時血量邏輯沒動），但**到達等級明顯貼近擊倒數**了——
這正是「升級主要靠殺怪」該有的樣子。10 分鐘場次下，wpm=10 的學生改版前
會衝到 LV30，改版後穩定在 **LV16 左右**，不會整堂課等級亂飆。

> **只有一個等級**。怪物等級＝玩家等級（升級後下一隻才跟上，當前那隻不會變強）。
> 畫面上不要出現兩種等級，中年級會混亂。

## 7. 難度層級（取代動態難度）

**動態難度（DDA）已經移除。** 每位學生有一個固定的**難度層級**，
新手教學量出來之後就定下來，之後每一場都用同一條曲線。

### 7.1 為什麼要拿掉 DDA

DDA 原本的工作是「不要讓學生一直卡在同一隻」，它做到了。
但它有一個致命的副作用：**它會把學生變強的效果全部吃掉**。

```
點了天賦「傷害 +10%」→ 怪死得快 → 這場擊倒變多
                    → 下一場 DDA 把怪血調厚 → 擊倒數回到 4～8 隻
```

結果是「變強」永遠不會反映在畫面上。要做局外成長（[`META-GROWTH.md`](META-GROWTH.md)），
就必須有一條**不會反過來追著玩家跑**的難度線，變強才有地方顯現。

固定曲線的代價也要講清楚：**DDA 的那份工作要有人接手**。
接手的是「層級」——只是它在**開場分一次**，而不是每場調一次。

### 7.2 三個層級

| 層級 | 觸發門檻（教學量到的 wpm） | ctk0 | slope | 經驗倍率 | 點數係數 |
|---|---|---|---|---|---|
| **初階** | < 6 | 2.0 | 0.30 | ×1.00 | ×0.8 |
| **中階** | 6 – 13 | 4.0 | 0.52 | ×1.25 | ×1.4 |
| **高階** | ≥ 14 | 6.0 | 0.85 | ×1.50 | ×2.0 |

用雲端 187 筆 `bestWpm` 實測分布（p25=6、中位=10、p75=15）套這組門檻，
班上大約分成 **23% / 52% / 25%**。

「經驗倍率」與「點數係數」是層級的**補償**：層級越高怪越硬、擊倒數越少，
但每一隻給的經驗與成長點數越多。§7.5 會驗算這個補償夠不夠。

### 7.3 層級怎麼決定

1. **新手教學量一次**（機制見 §7.0）。教學全程累積的 `wpm` 直接對照 §7.2 的門檻。
2. **量到的值偏低是正常的**：第一次進戰場還在認介面、找鍵位，
   教學量到的 wpm 通常比之後的 `bestWpm` 低 20～30%。門檻已經按這個偏差抓過。
3. **跳過教學**（老師示範用）→ 一律給**中階**。
4. **舊學生沒有教學紀錄**：用現有的 `bestWpm` 直接對照門檻補一個層級，
   不用叫他們重打教學（遷移方式見 §7.6）。

### 7.4 層級會變，但不是每場都變

這是跟 DDA 最重要的差別：**層級是「稀有、看得見、學生知情」的事件**，
不是背後偷偷轉的旋鈕。

- **升層要學生自己按**。營地顯示「你最近五場的速度已經到 中階 的標準了，
  要挑戰嗎？」，按下去才換。**不會自動升**——被系統偷偷調難的感覺很差。
- **升層條件**：最近 5 場的 `lastWpm` 中位數達到下一層門檻 **+2**
  （遲滯，避免在門檻上來回跳）。
- **降層只有老師能做**。孩子自己按上去之後打不動，找老師調回來；
  系統不會自動降，那等於在說「你退步了」。
- **老師隨時可以指定任何學生的層級**（教師控制台 → 班級數據圖旁邊）。
  老師比任何公式都清楚這個孩子今天狀況如何。

### 7.5 驗算：升層那一步會不會變虧

升層之後怪變硬、擊倒數一定下降，補償夠不夠？（2 分鐘場・普通・法杖）

| 學生 | 升層前 | 升層後 | 點數變化 |
|---|---|---|---|
| wpm 6（初階頂 → 中階） | 5.0 隻 / 18 點 | 3.0 隻 / 21 點 | **+17%** |
| wpm 13（中階頂 → 高階） | 5.0 隻 / 29 點 | 4.0 隻 / 35 點 | **+21%** |

擊倒數掉了 40% / 20%，但靠 §7.2 的點數係數與經驗倍率補回來，**淨值是正的**。
升層是獎勵，不是懲罰——這條要守住，係數改動時要重跑這張表。

### 7.6 從 DDA 遷移

| 舊 | 新 |
|---|---|
| `mg_scores.dda`（70 筆有值） | **不再讀**，保留欄位不刪（回頭要比對時還查得到） |
| `BALANCE.dda.*` | 整段移除 |
| `seedDda()` / `updateDda()` | 移除 |
| `monsterHp(lv, quality, dda)` | 改成 `monsterHp(lv, quality, tier)` |
| 沒有 `tier` 的舊紀錄 | 第一次登入時用 `bestWpm` 對照 §7.2 補寫 `tier` |
| `dda.rescueAtPct` / `rescueCut`（開場 25% 還 0 擊倒就偷扣血） | **移除**。初階的 CTK 已經低到第一隻一個詞就倒，不需要偷偷放水 |

### 7.0 新手教學校準（層級的量測來源）

`seedNew: 0.85` 是「完全沒有任何資訊」時的保底值，但其實**第一次進入戰場時
就能實測**，不用用全班平均值瞎猜。所以新增一段**新手教學**（見
`docs/PLAN-v2.md` W3.5）：

* 只有**史上第一次登入**（`!MY_HIST || (!MY_HIST.tutorialDone && !MY_HIST.plays)`）
  會觸發，教完就不再出現。
* **一段一段來，不是唸說明書**：`TUTORIAL_SCRIPT` 是一條 caption（說明卡）／
  battle（實際打幾題）交錯的線性腳本。每把武器先給一句介紹＋2 題暖身，
  接著一張說明卡**先講清楚特殊攻擊會發生什麼**（例：「爆擊條集滿了！接下來
  是神射手模式……」），按下去才真的觸發那個特殊攻擊讓學生打一次——
  法杖詠唱、弓箭神射手、匕首連環斬三個都會真的體驗到，不是憑空唸過去。
  怪物全程用**中階**曲線（教學本身也要有點難度感，但不影響最後判定），
  同一場教學共用同一個 `G`（同一隻怪、同一條經驗條），只是每段換武器。
* **特殊攻擊是強制觸發的，不用等機率／倍數湊到**：詠唱／連環斬直接呼叫
  `pickStaffChant()` / `pickDaggerFlurry()`（`G.tutForceSpecial`），
  神射手直接給 `G.sharpLeft = BALANCE.sharpShots`（不靠爆擊條自然集滿——
  說明卡已經把「集滿了」講成既定事實，不能讓手感不好的學生打不出那句話）。
* **量測涵蓋全部三把武器、一般攻擊與特殊攻擊**：因為整段教學共用同一個 `G`，
  `G.words` / `G.typedChars` 是連續累積的，不是只看一小段。
* 教學結束不寫進排行榜（不叫 `saveScore` 的正式分支），
  只把量到的 `wpm` 丟進 `seedDda(wpm)`，寫成 `MY_HIST.dda` 與 `tutorialDone:true`
  （本機＋雲端都要寫，換電腦也不會重教一次）。
* **接下來那一場才是真的**：第一場正式戰就已經是「量出來的那個層級」，
  不再是全班一律同一個保底值。
* 教學跳過鍵給老師示範用（`#tutorial-skip`），任何時候按都能跳，
  跳過時一律給**中階**。

```
教學結束 → wpm = G.words / 教學實際秒數 × 60
           wpm <  6  → 初階
           6 ≤ wpm ≤ 13 → 中階
           wpm ≥ 14  → 高階
寫進 MY_HIST.tier 與雲端 mg_scores.tier（本機＋雲端都寫，換電腦不用重教）
跳過教學 → 中階
```

| 參數 | 值 |
|---|---|
| `tier.cutA` / `tier.cutB` | 6 / 14（教學量到的 wpm 門檻） |
| `tier.skipDefault` | `'B'`（跳過教學給中階） |
| 教學中怪物用的層級 | 中階（教學本身也要有難度感，但不影響最後判定）

## 8. 階級與單場評價

### 8.1 戰績分（跨版本、跨品質可比）

```
score = 每分鐘正確字數 × (1 + qBonus) × (0.85 + 0.15 × 正確率)
qBonus：普通 0　精良 0.10　史詩 0.20　傳奇 0.30
```

| 階級 | 門檻 | 用實測 139 筆試算的分布 |
|---|---|---|
| 見習生 | 0 | ~15% |
| 冒險者 | **4** | ~12% |
| 銅級勇者 | **7** | ~25% |
| 銀級勇者 | **11** | ~25% |
| 金級勇者 | **16** | ~15% |
| 傳說勇者 | **23** | ~8% |

徽章沿用現有 6 枚 SVG。歷史徽章看 `bestScore`（只升不降）。
登入畫面、結算畫面共用這一套。

### 8.2 單場評價（成就結算等級）

結算畫面新增一個大字母 **S / A / B / C / D**，算法（滿 7.5 分）：

| 項目 | 2 分 | 1.5 分 | 1 分 | 0.5 分 |
|---|---|---|---|---|
| 擊倒數 | ≥8 | 6–7 | 4–5 | 2–3 |
| 正確率 | — | ≥95% | ≥88% | ≥75% |
| 最高連擊 | — | ≥12 | ≥8 | ≥4 |
| 到達等級 | — | ≥12 | ≥8 | ≥5 |
| 比上一場進步（等級或傷害） | — | — | +1 | — |

`S ≥ 6`、`A ≥ 4.5`、`B ≥ 3`、`C ≥ 1.5`、`D` 其餘。
每個等第配一句**針對弱項**的話（例：B 且正確率 < 88% → 「慢一點打，正確率上來傷害自己會長」）。

## 10. 難度鎖改成看等級

舊的「單場擊倒 N 隻」已經不適用（新版人人都能擊倒 4 隻以上）。
改看**歷史最高到達等級 `bestLevel`**：

| 品質 | 解鎖條件 | 對應能力（實測） |
|---|---|---|
| 普通 | 一開始就有 | — |
| 精良 | `bestLevel ≥ 4` | 幾乎所有人第一場就開 |
| 史詩 | `bestLevel ≥ 8` | 約 wpm 12 以上 |
| 傳奇 | `bestLevel ≥ 12` | 約 wpm 23 以上 |

### ⚠ 場次長度變重要了（取消 DDA 的實際代價）

DDA 以前會把「場次多長」吸收掉——不管打幾分鐘，擊倒數都被拉回 4～8 隻。
**拿掉 DDA 之後，場次長度直接決定擊倒數與點數**：

| 10 分鐘 | 17.6 | 74 | 7.0× |

- **2 分鐘太短**：初階最慢的孩子只打得倒 2 隻，天賦加 30% 傷害也看不出差別
  （量化誤差比效果還大）。
- **建議 5 分鐘**：中位學生 9.8 隻、47 點，天賦效果看得出來，
  快慢差距也還沒放大到難看。
- 差距只剩兩個旋鈕可以控：層級的點數係數（§7.2）與單場點數上限（30 點／分鐘）。

### 天賦效果驗證（這是這次改版的重點）

同一個學生，傷害 +0% / +15% / +30%（10 分鐘場）：

| 層級 | 擊倒 | 到達 LV | 區域 |
|---|---|---|---|
| 初階 wpm 4 | 15.0 → 17.2 → 18.0 | 9.0 → 9.2 → 10.0 | 2 → 2 → 2 |
| 中階 wpm 10 | 17.5 → 20.0 → 22.0 | 12.0 → 13.0 → 14.0 | 3 → 3 → 3 |
| 高階 wpm 20 | 20.0 → 23.0 → 25.0 | 16.0 → 17.0 → 17.0 | 4 → 4 → 4 |

**+30% 傷害 = 多打倒 20%、多爬 1～2 級。**
同一組數字在 DDA 版本會被下一場的血量調整完全吃掉（擊倒數回到 4～8 隻），
這就是 §7.1 說的「局外成長要有地方顯現」。

> 區域（每 5 級一個區）對 +30% 還不夠敏感——要跨一個區得多爬 5 級。
> 如果希望「點了天賦就換一批怪」的感覺更明顯，把 `zoneWidth` 從 5 降到 4
> 是最便宜的改法（§6）。

### 品質比較

血量公式把品質倍率抵銷掉了（§3），所以不同品質的擊倒數本來就接近，
差別在「每下多重、題目多長」。詳細比較跑 `node tools/tier-sim.mjs` 自己看。

> **舊的 `tools/balance-sim.mjs` 有一個 bug（已修）**：`cps = Math.max(0.3, ...)`
> 給打字速度設了下限，等於把 wpm 3、4、6 的學生全部當成 wpm 18 來模擬，
> 所以舊版 §7 那張「最慢的學生也能推倒 6 隻」的表是**假的**——

## 12. 未來規劃（這次不做）

使用者已明確指示「先暫時不建立道具與配件」。以下保留設計空間：

   「+15% 傷害」「連擊上限 +40%」「經驗 +25%」「標點傷害翻倍」。

4. **區域選擇**：每 5 級給兩條路（多怪區／多經驗區）。
5. **班級共同目標**：全班合力解鎖新區域，跨堂課累積。
