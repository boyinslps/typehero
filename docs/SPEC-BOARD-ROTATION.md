## 一頁結論

| 項目 | 定案 |
|---|---|
| 張數 | **4 張**；主線任務和活動各要一張、而且不是同一張時，暫時 **5 張**（最多 5） |
| 組成 | **📌 目標**（主線／活動要打的；沒有就換成剛好）＋ **🔥 挑戰** ＋ **🎯 剛好** ＋ **🍃 輕鬆** |
| 強的上限 | 🔥 挑戰單 **①一次最多 1 張（≤25%）②只會是「你打過的最高星 +1」，不會更高 ③用你自己的打贏秒數估勝率，要 ≥55% 才放；沒有一隻達到就放那一星最好打的（不擋進度）④挑戰單連續 2 次沒打贏，換成那一星最好打的** |
| 不只看 HR | 輸入：區域進度 `zone`、圖鑑次數 `dex`、自己每隻魔物的最快秒數 `fastMk`（估速度）、最近打贏的單子、挑戰單連輸次數、主線任務、進行中的活動。**完全不看 HR** |
| 刷新 | **打贏一張 → 那張蓋「完成」章、留在原位**；全部蓋章 → 整批換新（2026-11-25 改版，見 `SPEC-SHOP-BOARD2.md` B）；輸、逃走、撤退、不算數 → **單子留著** |
| 手動刷新 | **「🔄 刷新」把沒完成、不是目標的單子整批換新**；每天第 1 次免費、第 2 次 40、第 3 次 80 字元，一天最多 3 次（`SPEC-SHOP-BOARD2.md` B1） |
| 過期 | **不會因為時間不見**；每天第一次打開看板時整理：只換掉「已經不適合」的（太舊的輕鬆單、任務做完的目標單），適合的留著 |
| 決定性 | 板子存在 `NW.board`（平的物件，鍵 `a`～`e` 固定），亂數＝`hash(種子｜變動次數｜格子)`；重整、關掉重開都是同一批 |
| 防刷 | **看板本身不給任何獎勵**（獎勵照場次給，跟 SPEC-BALANCE-V2 的一天前 4 場一致），換單子刷不到東西 |
| 驗算（480 秒＝V2） | 主線、活動要打的單子**不在板上 0 次**；2 張挑戰 0 次；沒有剛好／輕鬆可打 0 次；挑戰占比 9～23%；挑戰單勝率 p10 77～82%、p25 96～97%、p50 99%、p90 100%；進度**跟現行一樣或更快**（p10 草原★5 早 1～2 節，p50、p90 不變） |
| 上線 | 對已上線畫面的改動：**用旗標 `BOARD_ROT`**，開發時關著，老師點頭後打開；出事改回 `false` 就回到現在的全部列出，存檔不用動 |
| 待老師決定 | 3 題（§10），都有預設值 |

## 0. 目標與原則

### 0.1 孩子打開委託板應該感覺到什麼
1. **一眼看完、不被淹沒**：現在草原打完、森林打到 ★4 時板上有 **30 張**（2 區 × 3 隻 × 5 星），全部長得差不多。改成 4 張，三秒內看完。
2. **有「挑一張」的樂趣**：4 張各有角色——一張**想打的**（📌 任務／活動）、一張**有點挑戰的**（🔥）、一張**剛好的**（🎯）、一張**輕鬆的**（🍃）。不是只給一張（那就不是選擇）。
3. **今天心情不好也有得打**：輸了兩場想喘口氣，板上一定有 🎯 或 🍃。
4. **打贏有感覺**：撕下來、新的貼上去；下一張挑戰就是「下一顆星」。

### 0.2 研究依據
| 原則 | 依據 | 怎麼用 |
|---|---|---|
| 選項太多會不想選、選了也比較不滿意 | 研究（外部，待核）：Iyengar & Lepper 2000「24 種果醬 vs 6 種」；但 Scheibehenne 等 2010 的統合分析平均效果接近 0、各研究差很多；Chernev 等 2015 整理出**選項難比較、沒有明確偏好時**比較會發生 | 我們的單子長得像、孩子分不出差別（同一隻魔物 ★1～★5 各一張）——正是會過載的情況。4 張而且每張角色不同，好比較 |
| 工作記憶約 4 個項目 | 研究（外部，待核）：Cowan 2001 | 張數定 4；第 5 張只在任務＋活動同時有時才出現 |
| 認知負荷：功能越多越容易挫折，熟悉了再加 | 研究：REFS §4.1（Hodent） | 看板只放 4 張，其他資訊（地圖、掉落）照舊在右邊 |
| 心流：挑戰要跟能力相當；「令人愉快的挫折」 | 研究：REFS §1.1（GameFlow、Gee） | 🔥 一張、🎯 一～二張；挑戰單用**自己的秒數**估勝率，不用年級或 HR |
| 動態難度：用表現估難度，調的是**遭遇安排**而不是偷改數字 | 研究：REFS §1.1（Hunicke；Left 4 Dead 的 AI Director 調的是安排） | 只調「哪一隻貼上板」，**魔物血量、攻擊一律不變**；公開規則（連輸 2 次換好打的） |
| 自主：要有選擇 | 研究：REFS §1.1（SDT） | 4 選 1＋每天換 1 張，不是系統指定 |
| 失敗代價要低 | 研究：REFS §1.1（Gee） | 輸了單子留著，可以馬上再打 |
| 不只靠顏色 | 研究：REFS §3.2、§4.1（Game Accessibility Guidelines） | 角色用「圖案＋字」：🍃 輕鬆、🎯 剛好、🔥 挑戰、📌 任務、🎪 活動 |
| 刷新看板（bounty board）是動作 RPG 的慣例：一次幾張、完成一張補一張 | （經驗判斷）《魔物獵人》集會所、《暗黑》的懸賞 | 選「一張換一張」（§2.1） |

### 0.3 底線
1. **主線要打的那隻一定在板上**（任務「打草原任何 ★3」時，那一星還沒開，就放「往任務前進」的下一星）。
2. **活動指定的魔物與星級，只要已經開放就一定在板上。**
3. **進度不能比現在慢**：挑戰單（下一顆星）永遠在。
4. **看板不給獎勵**：換單、補單都不會多拿任何東西。
5. **存檔相容**：舊存檔沒有 `NW.board` 也正常；旗標關掉就回到現在的畫面。

## 1. 板子的結構

### 1.1 名詞
| 名詞 | 意思 |
|---|---|
| 候選單子 | 現行 `boardQuests(nw)` 的結果去掉鎖住的（所有「已開放區域 × 魔物 × 已開放星級」）。**這個函式不改**，旗標關掉時照舊用它 |
| 總星級 `E` | 草原 ★1～★5＝1～5，森林 ★1～★5＝6～10（`REGIONS` 的順序 × 5 ＋ 星級；以後新區域接著排） |
| 打過的最高 `Ef` | 已開放區域裡 `E(區域, zone[區域])` 的最大值；全新存檔 0 |
| 下一顆星 `En` | `Ef + 1`，而且那一星已經開放（`starOpen`）；`Ef = 0` 時沒有 `En`；全部打完時沒有 `En`（「全破」） |
| 速度係數 `φ` | 自己打贏的秒數 ÷ 標準時間 `stdSecs`（中位學生），取中位數。來源依序：`fastMk`（每隻魔物每星最快）→ `fastest`（每區每星最快）→ 都沒有就 1.3（假設比中位慢 30%，保守）。`fastMk` 的鍵沒有區域，同一隻取比較小的標準時間（估得偏慢＝保守） |
| 預估勝率 `P̂` | `Φ( ln( T ÷ (stdSecs × φ × 1.15) ) ÷ 0.25 )`。`T`＝這一場的上限：現在 300 秒（`BAL.timeLimit`，時間到就輸），V2 開了以後 480 秒（`NW_V2.cap`，逃走）。1.15＝「最快」比平常快約 15%（校準報告 §2.4）；0.25＝場與場的差異 0.2 加估計誤差 |

`P̂` **只用來決定貼哪一隻**，不顯示給孩子，也不影響戰鬥。

### 1.2 單子的角色（畫面上的標籤，每次畫面算，不存）
| 角色 | 條件 | 給孩子看的字 |
|---|---|---|
| 🔥 挑戰 | `E = En`（還沒打過的那一星）；全破時：最後一區 ★4、★5 中最硬的 3 張裡，第一張「還沒打贏過、而且 `P̂ ≥ 0.55`」的 | 🔥 挑戰：你還沒打過的星級，打贏就開放下一顆星 |
| 🎯 剛好 | `Ef − 1 ≤ E ≤ Ef`（`Ef ≤ 1` 時 ★1 都算） | 🎯 剛好：跟你打過的差不多 |
| 🍃 輕鬆 | `E ≤ Ef − 2` | 🍃 輕鬆：比較簡單，放心打、拿材料 |
| 📌 任務／🎪 活動 | 這張是主線或活動要打的（疊加在上面三種之上） | 📌 任務要打這張／🎪 活動要打這張 |

### 1.3 四個欄位與「強的上限」
欄位鍵固定 `a`～`e`（位置固定，補上來的單子貼回同一格；孩子會記得「第二張是挑戰」）。角色依優先順序認領：

| 優先 | 角色 | 怎麼挑 | 退路 |
|---|---|---|---|
| 1 | **目標 0**（主線） | §3.1 | 沒有主線目標 → 改成「剛好」 |
| 2 | **目標 1**（活動，第 5 張） | §3.2；跟主線是同一張就不另外放 | 沒有 → 不放（4 張） |
| 3 | **挑戰** | `E = En` 的候選裡 `P̂ ≥ 0.55` 的，照權重抽 1 張；**連輸 2 次**（`lose ≥ 2`）或沒有一隻達到 0.55 → `P̂` 最高的那一張（那一星最好打的）。**目標單本身是挑戰單時，這格改成「剛好」** | 沒有 `En`（全新存檔、全破又沒有魔王）→ 剛好 |
| 4 | **剛好** | 🎯 角色的候選裡 `P̂ ≥ 0.80` 的，照權重抽 | 都不到 0.80 → `P̂` 最高的；沒有 🎯 候選 → 輕鬆 |
| 5 | **輕鬆** | 🍃 角色的候選，**`E ≥ Ef − 4`**（不要太舊：森林 ★3 時不會還掛草原 ★1），照權重抽 | 沒有 🍃（`Ef ≤ 2`）→ 剛好 |

**強的上限（定案）**
| 規則 | 數字 | 理由 |
|---|---|---|
| 一次最多幾張 🔥 | **1 張**（4 張的 25%；5 張時 20%） | 研究（心流）：一張「有點難」夠了；兩張以上，怕輸的孩子會覺得板上一半都打不贏。驗算：板上 🔥 占比 9～23%，「2 張挑戰」0 次 |
| 最多高幾星 | **你打過的最高 +1**（就是解鎖規則允許的最高） | 現行列表本來就能選到最高開放星；看板不能比現在少。驗算：p25 以上的 🔥 勝率 96～100%，它其實是「下一步」不是「懲罰」 |
| 預估勝率下限 | **≥ 55%** | 低於一半的單子貼在板上，孩子點了大概會輸（「令人愉快的挫折」要做得到）。55% 不是 70%：太嚴的話中慢速的孩子永遠看不到炎牙狼（驗算：森林開了以後板上有狼 48～85%） |
| 不擋進度 | 沒有一隻達到 55% 時，**照樣放那一星最好打的** | 底線 3：p10 在 300 秒規則下草原 ★5 的勝率本來就低，不放就卡住 |
| 連輸 | **連續 2 次沒打贏挑戰單 → 自動換成那一星最好打的**，畫面說「🪜 換一隻比較好打的 ★N 給你試試」 | 研究（DDA）：調安排、公開規則；2 次是「再試一次」之後 |
| 剛好單 | `P̂ ≥ 0.80` | 「剛好」要真的打得贏；炎牙狼 ★4 在你用咕咕鳥打過 ★4 時不一定剛好 |

### 1.4 權重（同一種角色有好幾張候選時）
從 1 開始連乘：
| 條件 | 乘 | 為什麼 |
|---|---|---|
| 板上已經有同一隻魔物 | ×0.5 | 多樣：4 張盡量 4 隻不同 |
| 這張在最近 3 張打贏的裡面 | ×0.2 | 剛撕下來的不要馬上又貼回來 |
| 跟剛打贏的那張同一隻 | ×0.15 | 補上來的換一隻 |
| 這隻魔物還沒打倒過（`dex = 0`） | ×2 | 新魔物先出現（圖鑑、測試回饋都需要） |
| 🍃：離 `Ef − 2` 每遠 1 星 | ×1/(1+距離) | 輕鬆單別太舊 |
| 🎯：在「現在這一區」 | ×1.5 | 剛好單多半在你正在推的地方 |

主線目標只寫「這一區 ★N」時挑哪一隻（**不用亂數**，同一份進度一定同一隻）：`P̂ ≥ 0.55` 的（都不到就最好打的）裡，**先留板上已經有的** → 避開剛打贏的那隻 → 圖鑑次數少的 → 鍵名排序。

### 1.5 純函式（`nw-data.js`，參考實作在 `tools/nw-sim/board.mjs`）
```js
BOARD = { keys: ['a','b','c','d','e'], hardP: 0.55, midP: 0.80, phi0: 1.3, best2typ: 1.15, sig: 0.25, loseSoft: 2, recentN: 3, easyAge: 4 }
frontier(nw, T)              → { Ef, En, cleared, front, hardId }
phiHat(nw)                   → φ
pHat(q, φ, T)                → 0～1
band(nw, q, F)               → 'hard' | 'mid' | 'easy'
goalCards(nw, events, ctx)   → [{ id, kind: 'quest'|'event', why: 'target'|'path'|'event', match(q) }]（最多 2）
roleList(nw, goals, F)       → 例 ['goal0','hard','mid','easy']、['goal0','goal1','mid','mid','easy']
pickBoard(nw, now, seed, events = [], T)              → board（全新排一塊）
repair(nw, board, now, events, T, max, force = [])    → { board, changed: ['b', …] }
ensureBoard(nw, now, events, T, seedIfNew)            → { board, changed, why: 'new'|'day'|'same'|'fix' }
afterRun(nw, board, { id, win, valid, wasHard }, now, events, T) → { board, changed }
swapCard(nw, board, key, now, events, T)              → { board, changed, refused? }
normalizeBoard(d)            → board 或 null
```
`repair` 的步驟（決定性：每格的亂數是 `mulberry32(hash32(seed + '|' + n + '|' + 格子))`，`n` 每次整理 +1）：
1. `force` 的格子先清空（剛打贏的、按了換一張的）。
2. 現有的單子照角色優先順序**認領角色**（在哪一格都可以，格子不動）。單子不在候選裡、重複、或第二張 🔥 → 認領不到＝「不適合」。
3. 沒人認領的角色補進空格（先補 `force` 的格子——新單子貼回原位）。
4. 空格不夠才拿「不適合」的單子來換，**最多 `max` 張**；單子比角色多（例如活動結束）就撕掉不適合的，也算進 `max`。

| 呼叫的時機 | `max` | 結果 |
|---|---|---|
| 新存檔、舊存檔第一次、格式壞掉（`pickBoard`） | ∞ | 全部排 |
| 今天第一次打開看板（`ensureBoard`，`board.day ≠ twDay`） | ∞ | 只換不適合的；適合的留著 |
| 同一天再打開 | 0 | 只修壞掉的（重複、已經不開放）；其他一張都不動 |
| 打贏（`afterRun`） | 1 | 那一格補新的＋最多再換 1 張不適合的 |
| 連輸 2 次挑戰單 | 0 | 只換那一格 |
| 換一張（`swapCard`） | 0 | 只換那一格 |

## 2. 刷新規則

### 2.1 什麼時候補、補幾張（比較後選 A）
| 做法 | 對孩子 | 對一節課（新世界約 15 分鐘；p10 1 場、p50 2 場、p90 3～4 場） | 判斷 |
|---|---|---|---|
| **A 打贏一張 → 那一格立刻補一張** | 每場打完都看到「新的貼上來」，回饋最即時 | 慢手一節 1 場也會換到新的；下一顆星馬上出現 | **選這個** |
| B 打贏 2 張才一起換 | 打完一張板上少一張，孩子會問「怎麼沒有了」 | p10 一節只打 1 場，要隔週才換；挑戰單打完下一星要等 | 不選 |
| C 4 張全部打完才換 | 有「清空」的爽感 | 快手被迫打不想打的 🍃；慢手好幾週看同一塊板 | 不選 |
| D 每天（每節課）整塊換 | 每次都新鮮 | 上週想打的那張不見了；跟「打完才刷新」的要求相反 | 不選，只用來**整理不適合的**（§2.4） |

### 2.2 結果怎麼算
| 結果 | 單子 | 其他 |
|---|---|---|
| 打贏（`result === 'win'` 而且 `valid`） | **蓋「✅ 完成」章、留在原位（不能再打、不能刷新）**，不單張補；`done + 1`、記進 `recent`。每張有單子的格子都蓋章 → 自動整批換新；主線的新目標不在沒蓋章的單子裡且有空格 → 直接貼進空格（`SPEC-SHOP-BOARD2.md` B1、B3） | 打贏的是挑戰單 → `lose = 0` |
| 輸（倒下）、時間到（現行）、逃走（V2）、撤退 | **留著**，可以馬上再打 | 是挑戰單 → `lose + 1`；到 2 → 換成那一星最好打的 |
| 不算數（`valid === false`，答不到 3 題） | 什麼都不變 | — |
| 打的單子不在板上（另一個分頁、之後 3a 加入同學的房間） | 什麼都不變 | 進度、圖鑑照常 |

「挑戰單」＝打之前它的角色是 🔥（`wasHard`，在 `finishHunt` **更新 zone 之前**算）。

### 2.3 手動「刷新」（2026-11-25 改版，取代原本的「換一張」；細節在 `SPEC-SHOP-BOARD2.md` B1、B3）
- 把「**沒蓋章、不是 📌 目標單**」的單子**一次全換**（`refillAll(…, 'swap')`）；蓋章的、目標單留著。🔥 那格刷新後**還是 🔥**，只換一隻魔物。
- **每天（`twDay`）第 1 次免費、第 2 次 40、第 3 次 80 字元，最多 3 次**（`BOARD.swapCost = [0, 40, 80]`）；存 `board.swap = twDay`、`board.swapN`、`board.swapCoin`；重整頁面不會回復。
- 換掉的單子記在 `board.out`（平的字串陣列，最多 8 個），當天不會又出現；隔天清成 `[]`。
- 沒有可以換的（全是蓋章或目標單，或別張都換不到）→ 按鈕灰掉、不扣次數、不扣字元。
- 扣字元由 `newworld.js` 做（純函式只回 `cost`）；為什麼要收費：快手每節結餘多，可以多刷 1～2 次，但一天最多 3 次，擋「一直換到出現想要的」。

### 2.4 會不會過期
**不會因為時間不見。** 每天第一次打開看板時整理一次（`ensureBoard`），只換掉已經不適合的：
- 任務做完了的目標單、活動結束的活動單（這兩張若還適合當別的角色就留下，只是不再有 📌／🎪）；
- 太舊的輕鬆單（`E < Ef − 4`）；
- 進度往前跑了，原本的「剛好」變成第二張「輕鬆」→ 換成剛好。
孩子可以這樣理解：「單子不會自己不見，除非它變得太簡單了。」

### 2.5 決定性
- 板子存在存檔裡（§5），重整、關掉重開直接讀存檔，**不重新抽**。
- 要抽的時候（補單、整理），亂數只由 `seed`、變動次數 `n`、格子鍵決定；兩個分頁從同一份存檔做同一件事，結果相同。
- `seed`＝第一次建板時 `hash32(文件ID + ':board1')`（同一個學生在兩台電腦第一次打開也是同一塊）。只存在自己的存檔裡，不對外。

## 3. 跟其他系統的關係

### 3.1 主線任務（不能卡住）
- 目標任務的找法跟 `newworld.js` 的 `checkQuests` 同一個順序：跳過做完的、`hold` 的；`soft` 而且沒有 `target` 的跳過（例如 `1-0a` 教學大樓）；**遇到第一個有 `target` 的就是它**；遇到「不是 soft、也沒有 target」的（`1-3` 閃避防禦各 5 次）就停——那時主線不需要特定單子（任何單子都能練）。
- 目標的星級**已經開放** → 貼那一張（`1-1` 泡泡蛙 ★1、`1-2` 咕咕鳥 ★1、`1-4` 草原任何 ★3、`1-7` 草原任何 ★5）。
- **還沒開放**（例如 `1-4` 要 ★3，你才打到 ★1）→ 貼**往任務前進的那一張**（草原 ★2，就是挑戰單），標「📌 往任務前進」。所以「主線要的星級」與「進度」永遠同一張，不會多一張 🔥。
- 看板上方的任務橫幅照舊；**目前任務是建築（教學大樓、鐵匠鋪）時**，橫幅的後半句改成「→ 去村莊的「教學大樓」」（現在一律寫「選有紅色標籤的委託單」，對建築任務是錯的，順手修）。
- 驗算：主線要的單子不在板上 **0 次**（每組 1,800～6,000 次打開看板）。

### 3.2 活動（`hunt`／`classwar`／`ranking`）
- 交給看板的活動：進行中、自己班看得到、**有指定魔物**、而且自己還沒達標（`hunt` 看 `eventProgress().done`、`classwar` 看 `mineReached`；`ranking` 沒有達標，一直交）。`boost`、沒有指定魔物的活動不需要單子（任何單子都算），看板上方加一行「🎪 活動中：打贏哪一張都算」。
- 星級：活動魔物所在的區域**從最新的往回找**，挑 `min(最高開放星, max(活動最低星, 這區打過的最高星))`。
- 剛好跟主線同一區同一星：主線只要「這一區 ★N」→ **合成一張**（用活動的魔物）；主線指定了別隻 → 活動退一星（還 ≥ 最低星的話）。所以有活動時 🔥 照樣最多 1 張。
- 活動單**打贏後會貼回同一張**（目標角色不看「最近打贏過」），`ranking` 的最快討伐可以一直刷自己的紀錄。
- 活動要的星級還沒開放（例如 ★3 以上的炎牙狼，你森林才 ★1）→ 不貼，上方一行「🎪 活動「…」要打 ★3 的炎牙狼，先把迷霧森林打到 ★2 喔」。這跟現在一樣（現在也打不到），**看板沒有多擋**。
- 活動是非同步讀的（`EV.load`）：看板用當下的快取；活動晚到就下次打開才貼。驗算：活動單不在板上 **0 次**。

### 3.3 教學大樓
不經過看板（稻草魔物在教學大樓裡），不受影響。`1-0a` 是 soft，不擋看板的目標（§3.1）。

### 3.4 SPEC-BALANCE-V2（雙軌、一天前 4 場、防刷、慢手流派）

## 5. 存檔與相容

### 5.1 新欄位 `NW.board`
```js
board: {
  v: 1,                 // 格式版本；不是 1 就丟掉重排
  seed: 2915430571,     // 整數
  day: 20781,           // 上次整理的 twDay
  n: 12,                // 變動次數（每次 repair +1）：亂數用，也給雙分頁比大小
  done: 7,              // 打贏撕掉的單子總數
  swap: 20781,          // 上次刷新的 twDay（0＝沒刷新過）
  swapN: 1,             // 今天刷新了幾次（0～3）；換日歸 0
  swapCoin: 40,         // 刷新總共花的字元
  lose: 0,              // 挑戰單連續沒打贏幾次（0～9）
  last: 'grass:coo:3',  // 上一張打贏的
  recent: ['grass:coo:3', 'grass:frog:2'],   // 最近 3 張打贏的：平的字串陣列
  out: [],              // 今天刷新換掉的單子（最多 8 個，不要又換回來）：平的字串陣列
  slots: {
    a: { id: 'grass:shroom:4', k: 'goal0', at: 20781, m: 0, ok: 0 },  // k＝這格認領的角色；at＝貼上的 twDay；m＝這張沒打贏幾次；ok＝蓋章了沒（0／1）
    b: { id: 'grass:frog:3', k: 'mid', at: 20780, m: 1 },
    c: { id: 'grass:coo:2', k: 'mid', at: 20779, m: 0 },
    d: { id: 'grass:shroom:1', k: 'easy', at: 20779, m: 0 },
    e: { id: '', k: '', at: 0, m: 0, ok: 0 }                          // 空格也要有：五個鍵一定都在
  }
}
```
- **Firestore 限制**：只有物件、字串、整數、一個平的字串陣列；沒有陣列裡的陣列、沒有 `undefined`。`board.mjs` 的 `firestoreOk()` 每一步都檢查。大小約 600 位元組。
- **五個鍵一定都在**：`pushCloud` 是 `setDoc(…, { merge: true })`，Firestore 的 merge 會**往下合併物件**，本機刪掉的鍵雲端刪不掉，下次讀回來又出現。所以空格用 `{ id: '' }`，不刪鍵。
- **不改 Firestore 規則**：`mg_scores` 是整份存，`nw` 底下沒有欄位白名單。

### 5.2 舊存檔
- `defaultNw()` 加 `board: null`。
- `normalizeNw` 加 `o.board = normalizeBoard(d.board)`：不是物件、是陣列、`v !== 1` → `null`；欄位逐一夾範圍（整數 ≥0、`lose ≤ 9`、`m ≤ 99`）；`id` 必須符合 `/^[a-z]+:[a-z]+:[1-5]$/`，**重複的第二張清空**；`recent` 只留合法的前 3 個。
- `null` 的存檔：第一次打開看板（旗標開著）時用 `pickBoard` 照目前進度排，存檔。**舊存檔的第一塊板子就是「照現在的進度」排的**，不會從 ★1 開始。
- 旗標關掉：完全不讀寫 `NW.board`（留在存檔裡也無害）。

### 5.3 兩個分頁互蓋
- 板子**不是獎勵來源**，所以互蓋的最壞情況只是「一張打過的單子又出現一次」或「少補一張」，**不會多給東西**——這是故意的設計（防刷的根本）。
- 整份存檔照舊用 `savedAt` 選新的（`loadNw`）；打開看板前比照 `syncGear`：雲端 `savedAt` 比自己新就先換成雲端的，再 `ensureBoard`。
- merge 合併出「兩格同一張」：`normalizeBoard` 清掉重複，同一天打開時 `ensureBoard` 只把那一格補回來（`why: 'fix'`）。
- `n`、`done` 只增不減，之後要做更細的合併（例如以 `n` 大的為準）可以用；第一版不需要。

2. **入口頁（pcclass `TYPEHERO_UPDATES`）要不要寫？** 預設 **不寫**：新世界仍在試玩階段、要打完標點挑戰才進得去，入口頁只寫全班都玩得到的（`ANNOUNCEMENT-GUIDE` §六）。只寫新世界佈告欄與版本紀錄。
3. **怎麼上線？** 預設 **做完直接開給全部**（旗標打開）：不改戰鬥與獎勵、可以一鍵退回。另一個選項是先在一節課請幾位同學試（老師在那台電腦用 localhost 旗標看），再全開。
