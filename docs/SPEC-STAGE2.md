## 0. 目的、範圍、不做的事

### 0.1 一句話
- **2a 榮譽碑**：讓「打得比以前更好」被看見，又不讓亂打、貼上、改數字的紀錄上榜，也不讓排在後面的孩子難過。
- **2b 鐵匠鋪＋倉庫**：存了好幾週的材料和圖紙終於有用途。打怪 → 材料 → 打造／強化 → 角色變強、變帥 → 打得動更難的魔物。

## 1. 開放方式：2a、2b 分開開

### 1.1 為什麼要分開
- `rank`、`forge`、`storage` 現在都是 `wip: 2`，`buildingOpen()` 用 `parseFloat(b.wip) <= openStage()`，**沒辦法只開其中一個**。
- 兩塊的風險不同：2b 全部存在自己的 `mg_scores.nw`，**不用改規則**；2a 要新集合、要改 `mg_nw_flags` 規則，老師要重貼規則。
- 建議順序（§8 第 1 題）：**先開 2b，同時默默開始寫 `mg_nw_runs`；兩週後開 2a**。理由：
  1. 鐵匠鋪是孩子等最久的（鐵匠 NPC 一直說「快好了」、施工中視窗寫「你已經存了 N 個材料」）。
  2. 「進步」榜要有「以前的紀錄」當基準，先寫兩週紀錄，2a 一開就有資料。
  3. 裝備會讓討伐變快：先有裝備、再開最快討伐榜，榜才不會開張兩週就被「裝備出來前」的舊紀錄卡住（經驗判斷）。

### 1.2 程式改法
```js
// nw-data.js：段號改成字串，開了哪幾段用清單表示（可以跳著開）
export const OPEN_STAGES = ['1'];                 // 開 2b → ['1','2b']；再開 2a → ['1','2b','2a']
export const openStages = () => (location.hostname === 'localhost' && window.__NW_STAGES__) || OPEN_STAGES;
export const stageOpen = s => openStages().includes(String(s));
export const buildingOpen = b => !!b.act && (!b.wip || stageOpen(b.wip));
```
- `VILLAGE.buildings`：`rank` → `wip: '2a'`；`forge`、`storage` → `wip: '2b'`；`rooms` 維持 `'3a'`；`shop`、`armor` → `'3b'`；`star` → `'5'`。施工中視窗的「第 N 段開放」照字串顯示。
- 舊的 `OPEN_STAGE`／`openStage()` 刪掉；`window.__NW_STAGE__` 測試改成 `__NW_STAGES__`（陣列）。`tools/browser-test/` 用到的地方一起改。
- 主線、詞條、結算文字裡「鐵匠鋪開張就能用」這類句子，改成看 `stageOpen('2b')`。
- `docs/RELEASE-STAGES.md` 的「怎麼開下一段」第 2 步同步改寫。

### 1.3 退回
- 收回某一段：從 `OPEN_STAGES` 拿掉那個字串、重新發版。**資料不刪**：做好的裝備還在存檔裡；2b 收回時戰鬥照常套用已穿的裝備（不然孩子會覺得被沒收），只是進不了鐵匠鋪。
- 2a 收回：榮譽碑變回施工中；`mg_nw_runs` 照寫（不影響學生）。

## 2. 2a 榮譽碑

### 2.1 設計目標（先想要孩子感受到什麼，再回推規則；研究：MDA，§1.1）
1. **「我變厲害了」被看見**（勝任感，研究：SDT §1.1）。所以預設打開的是「進步」榜，跟自己比。
2. **排在後面的孩子不會難過**：低名次會打擊動機，相對、分程度的榜比較不傷人（研究：arXiv 2305.08346、NSF 相對榜研究，§2.1）。所以：只列前 10＋自己、榜外不顯示第幾名、分年級、只顯示「往上」的變化。
3. **亂打的人上不了榜**：第 2、3 道防線（GDD §20.3～20.4）。客戶端算的分數本來就不可信，重要名次交給人看（研究：Supercraft／Bugnet，§2.1）。
4. **不造成「怕錯過」**：沒有倒數、沒有「本週最後機會」（研究：ACM／vzbv／ICO，§2.1）。

### 2.2 四個分頁

| 分頁（順序＝畫面順序） | 比什麼 | 為什麼這樣定 | 進榜門檻 |
|---|---|---|---|
| 🌱 **進步**（預設打開） | **最近兩週**最好的一場「打字速度」比**兩週以前**最好 3 場的平均快幾 %。顯示「打字變快 18%」 | 跟自己比，每個人都有機會；兩週＝兩節課，一週一節的節奏下才有東西可比。用打字速度不用討伐秒數：**裝備不會影響它**，比的是真的手變快 | 以前至少 2 場合格紀錄、最近兩週至少 1 場 |
| ⚡ **最快討伐** | 選魔物＋星級，最快秒數（只算打贏） | GDD §20.1「技術與配裝」：這一榜**配裝也算**，名字旁邊標武器圖示和戰力，讓孩子知道「做裝備也會變快」 | 那一場正確率 ≥ 90% |
| 🎯 **神準名單** | 最近 10 場 Lv10 以上的合格場次，平均正確率 ≥ 97% 就上名單。**不排名次** | 真實資料正確率中位數是 100%（GDD §3.1），排名次會有幾十個人並列第一，沒意義；改成「達標就上」的里程碑，跟抓蟲徽章同一個思路（研究：SPEC-TEACHER-ADMIN §12 里程碑） | 10 場（約 5 節課）。GDD 原本寫 Lv20 以上，但森林最高 Lv22，只有 ★5 夠，改 Lv10 |
| ⭐ **獵人等級** | HR | 獎勵「持續來玩」。它比的其實是玩多久，見 §8 第 4 題 | HR ≥ 2 |

- GDD 的「圖鑑」榜拿掉：現在只開 4 隻魔物，一兩節課就全打過，大家都並列。之後魔物變多再考慮。
- **分年級**：四、五、六年級各一張榜（§8 第 3 題）。四年級跟六年級手速差很多，放一起只會讓四年級永遠上不了榜（經驗判斷；研究：相對榜／分程度，§2.1）。

### 2.3 顯示規則（全部分頁共用）
- 列：`名次徽章（前 3 名金銀銅，PX.badge）｜504・5號｜名字｜分數`。名字＝`displayName(mg_scores.name)`（v3.14.1 起是登入名字）；老師在 `mg_bugboard.hideNick` 隱藏的人顯示「神秘獵人」。**名字在彙總時就寫好**（§2.7），學生端不另外讀。
- **前 10 名＋自己**。自己在前 10 就把那一列框金色。
- **自己不在前 10：不顯示第幾名**，只寫差多少：
  - 進步：「再快 3% 就上榜！」
  - 最快：「再快 4.2 秒就上榜！」
  - 獵人等級：「再升 2 級就上榜！」
  - 還沒有合格紀錄：寫怎麼拿（「打贏一場、正確率 90% 以上，就會有紀錄」）。
- **比上週**：名字右邊只顯示 **▲3**（上升 3 名）或 **🆕 新上榜**；**下降不顯示**（經驗判斷：GDD 要「比上週進步幾名」，但對孩子來說「▼5」只是在公開說你退步了）。
- 神準名單：顯示最近達標的 20 人（新的在前）＋「還有 N 人也很準！」；自己沒達標寫「最近 10 場平均 95%，到 97% 就上名單」或「Lv10 以上再打 4 場」。
- 頂端一行小字：「榮譽碑每週更新，上次：11 月 18 日」（§2.7 的彙總時間）。自己最新的紀錄比榜上的好時，自己那一列寫「老師下次更新就會算進去」。

### 2.4 第二道防線：進榜條件（GDD §20.3）
一場要**同時**符合才是「合格場次」：
1. `res.valid`（現有：打贏或答 ≥ 3 題）。
2. **正確率 ≥ 90%**（`RANK_MIN_ACC = 0.9`）。
3. **有寫進 `mg_nw_runs`**（只看那一筆，所以速度、正確率、時間一定來自同一場）。
4. 沒有被第三道標記，或已經被老師按「沒問題」。
5. 不在老師的「先不上榜」名單（§2.10）。

不合格的場次照樣拿掉落、經驗、字元。結算畫面（`showResult`）多一行：
- 正確率不到：「這場正確率 82%，要 90% 才會上榮譽碑喔」。
- 被標記：「這場紀錄要等老師看過才會上榮譽碑」。**不寫「作弊」「可疑」**（GDD §20.4）。
- 合格且破了自己的紀錄：「🏆 新紀錄！下次榮譽碑更新就會算進去」。

### 2.5 第三道防線：可疑紀錄偵測（GDD §20.4）

戰鬥中要多記的東西（`nw-battle.js`，全部在本機算，結束時放進 `res`）：
- 每題：字數、按鍵數、作答毫秒、打對幾個字 → `q: [[字數, 按鍵, 毫秒, 對], …]`（最多 120 題）。
- 按鍵數：輸入框的 `keydown`，**算 `e.key === 'Process'`（注音輸入法組字時的鍵）與一般字鍵、Backspace**，不算 Enter、Esc、Ctrl、Alt、Shift（Ctrl／Alt 是換線與舉盾）。
- 按鍵間隔：同一題內相鄰兩鍵的間隔（只算 < 2 秒的），用累加的平均與標準差（Welford），不存每一鍵的時間。
- `act`＝各題作答時間加總（秒）；`cpm`＝打對的字 ÷ `act` × 60（打字速度，進步榜用）。

| 代碼 | 學生看不到；老師頁顯示 | 判斷 | 抓什麼 |
|---|---|---|---|
| `keys` | 按鍵太少 | 打對的字數 > 按鍵數 ÷ 1.5（整場打對 ≥ 20 字才判斷；注音一個字至少 2 鍵） | 貼上、外掛輸入 |
| `fast` | 太快 | 任一題（≥ 3 字）每秒超過 5 字，或整場 `cpm` > `CPM_SANE`（暫定 130 字/分：舊世界全校最快 85 字/分 × 1.5） | 異常速度 |
| `even` | 節奏太平均 | 間隔 ≥ 40 個，標準差 ÷ 平均 < 0.12 | 連點程式 |
| `sum` | 數字對不起來 | 各題「對」加總 ≠ 整場打對字數，或題數 ≠ 已答題數，或各題毫秒加總 > 整場秒數 + 1 | 開主控台改數字 |
| `jump` | 進步太跳 | 這場 `cpm` > 自己前 5 場 `cpm` 中位數的 3 倍（有 5 場才判斷；存 `NW.cpmHist`，最多 5 個） | 換人代打 |
| `paste` | 試著貼上 | `flags.paste` ≥ 3（貼上本來就被擋，但一直試就記一下） | 想用貼的 |

- 門檻寫成常數放 `nw-data.js` 的 `SUS`，**老師端彙總時用同一套函式重算一次**（§2.7），學生改了自己的程式也會在老師那邊被抓到。
- 被標記 → 寫 `mg_nw_flags/run_{runId}`（§2.6），在老師按之前不上榜。
- 標記**不刪、不罰、不扣獎勵**。
- 門檻上線後看資料再調：第一週老師頁會列出所有被標的場次，誤判多就放寬（經驗判斷）。

### 2.6 `mg_nw_runs`：每場一筆

**什麼時候寫**：每一場 `res.valid` 的狩獵結束（`finishHunt` 之後），不管合不合格、輸贏都寫（進步榜與神準名單要用到輸掉的場次的打字速度與正確率）。**2b 上線就開始寫**（§1.1），2a 開之前沒人讀。

```js
// mg_nw_runs/{班級_座號}_{t}　　（固定 ID：逾時重送同一筆不會變兩筆）
{
  id: '五年級4班_5', cls: '五年級4班', seat: 5, uid: request.auth.uid,
  t: 1763500000000,            // 本機時間，只拿來組 ID
  ts: serverTimestamp(),       // 規則要求＝request.time：週、兩週的切法用它，改電腦時間沒用
  v: 1, app: '3.15.0',         // 紀錄格式與遊戲版本
  mk: 'coo', rk: 'grass', star: 3, lv: 6, res: 'win', secs: 84.2,
  acc: 0.957, ans: 31, cor: 88, typ: 92, keys: 214, act: 61.3, cpm: 86.1,
  iv: [182, 61, 207],          // 按鍵間隔：平均毫秒、標準差、個數
  fl: { fast: 0, paste: 0, wrong: 1 },
  sus: [],                     // §2.5 的代碼
  w: 'dagger', atk: 108, pw: 45, tier: 'B',   // 武器、攻擊力、戰力（2b 之後才有值）
  q: [[2, 5, 2100, 2], …]      // 每題摘要
}
```
- 大小：一場約 1～2 KB；全校一週約 600 場 ≈ 1 MB，一學期十幾 MB，免費額度內。
- **寫不進去（離線、逾時）**：放進 `NW.runQ`（最多 5 筆，多的丟最舊的），下次進村或下一場結束時補寫。補寫時 `ts` 是補寫的時間，彙總用 `t` 與 `ts` 差超過 1 天就只算進「現在」這一週（經驗判斷：避免改電腦時間塞舊紀錄）。
- 被標記時另寫：`mg_nw_flags/run_{runId}` `{ type:'run', status:'pending', docId, cls, seat, name, runId, why:[…], mk, star, t }`。

**規則**（`firestore-rules.txt`，要請老師重貼；`tools/rules-test/` 補案例）：
```
match /mg_nw_runs/{run} {
  allow read: if isTeacher();            // 學生端不讀紀錄（榜單讀 mg_nw_board）
  allow create: if signedIn()
    && request.resource.data.keys().hasOnly(['id','cls','seat','uid','t','ts','v','app','mk','rk','star','lv','res',
         'secs','acc','ans','cor','typ','keys','act','cpm','iv','fl','sus','w','atk','pw','tier','q'])
    && request.resource.data.uid == request.auth.uid
    && run.matches(request.resource.data.id + '_[0-9]+')   // 文件 ID＝班級_座號_時間
    && request.resource.data.ts == request.time
    && request.resource.data.secs is number && request.resource.data.secs >= 0 && request.resource.data.secs <= 310
    && request.resource.data.acc is number && request.resource.data.acc >= 0 && request.resource.data.acc <= 1
    && request.resource.data.star is int && request.resource.data.star >= 1 && request.resource.data.star <= 5
    && request.resource.data.q is list && request.resource.data.q.size() <= 120
    && request.resource.data.sus is list && request.resource.data.sus.size() <= 6;
  // 逾時重送：內容一樣就放行（ts 會不一樣，所以比對時排除 ts）
  allow update: if isTeacher()
    || (request.resource.data.diff(resource.data).affectedKeys().hasOnly(['ts'])
        && request.resource.data.ts == request.time);
  allow delete: if isTeacher();
}
match /mg_nw_flags/{flag}：type 清單加 'run'，欄位清單加 'runId'、'why'（why 是 list、size() <= 6）
match /mg_nw_board/{doc}         { allow read: if signedIn(); allow write: if isTeacher(); }
match /mg_nw_board_private/{doc} { allow read, write: if isTeacher(); }
```
- 現行規則 `mg_nw_runs` 是「登入者都能讀」；改成只有老師讀，因為紀錄裡有每題的時間，沒必要給同學看（經驗判斷）。
- `uid` 是匿名登入的 uid，換電腦就會變，**不是身分驗證**；用途是讓老師看出「同一個座號一週內出現 3 個以上不同的 uid」這種代打或冒名寫紀錄的跡象（§2.10 標 ⚠）。

### 2.7 榜單資料從哪裡來：老師端彙總（`mg_nw_board`）

**誠實說**：學生能寫任何人的 `mg_scores`、能用主控台寫出「看起來合理」的 `mg_nw_runs`。純前端只能**提高作弊成本＋讓老師看得到**，做不到不可能（研究：客戶端分數不可信，§2.1；SPEC-TEACHER-ADMIN §1.1）。

所以榜單不讓學生端自己算，而是**老師端彙總、寫成只有老師能寫的榜單文件**：

```
學生打一場 ──► mg_nw_runs（只能新增、ts 是伺服器時間）
          └─► 被標記 ──► mg_nw_flags/run_…（只有老師讀）
老師打開管理頁 ──► teacher/rank-calc.js 讀「上次之後的新紀錄」
                    ├─ 用同一套 SUS 函式重算（學生改自己的程式也會被抓）
                    ├─ 排除：待審核、不採計、先不上榜名單
                    ├─ 更新每個學生的累積狀態（mg_nw_board_private/{年級}）
                    └─ 寫 mg_nw_board/{年級}（所有學生只讀這一份）
```

| 資料 | 在哪 | 誰寫 | 學生改得了嗎 | 怎麼辦 |
|---|---|---|---|---|
| 每場紀錄 | `mg_nw_runs` | 學生（只能新增） | 能偽造新的，改不了舊的 | 老師端重算 SUS；⚠ 低於合理下限（`FASTEST_FLOOR` 依攻擊力換算）、進步 > 60%、uid 太多；**新的前 3 名先給老師看**（§8 第 5 題） |
| 榜單 | `mg_nw_board/{年級}` | 只有老師 | 不能 | — |
| 累積狀態、先不上榜名單 | `mg_nw_board_private/{年級}` | 只有老師 | 讀都讀不到 | — |
| HR | `mg_scores.nw.hr` | 學生 | 能 | 彙總時比對「HR 合理上限」（依該生 `mg_nw_runs` 場數與信件經驗估算 ×1.3＋3），超過標 ⚠ 不上榜 |
| 裝備、字元 | `mg_scores.nw` | 學生 | 能 | 只能抽查：教師頁學生卡顯示戰力與場數，戰力明顯超過「場數能做出來的」標 ⚠（§3.12） |

**什麼時候更新**（§8 第 2 題）：
- 老師打開 `teacher.html` 的「總覽」時，上次更新超過 6 小時就**自動更新**（不用多按）；🏆 分頁有「現在更新」。
- 「比上週」：每次更新存名次；台灣時間（`twDay`）跨到新的一週（週一開始，`twWeek = floor((twDay + 3) / 7)`）後第一次更新，把上一週最後一次的名次搬到 `prev`。
- 老師很久沒開管理頁 → 榜單停在上次，頂端寫更新日期。這是刻意的取捨：**榜單慢一點，換來學生改不到榜**。

**`mg_nw_board/{年級}`**（`'4'`、`'5'`、`'6'`；一份約 20～30 KB，遠低於 1 MB）：
```js
{
  t, week,                                   // 更新時間、第幾週
  improve: [{ id, c: '504', s: 5, n: '王小明', v: 18, up: 2 }, …10],   // up：比上週上升幾名；0 不顯示；-1＝新上榜
  fast: { 'coo:1': [{ …, v: 41.3, w: 'dagger', pw: 45 }, …10], 'wolf:3': [...] },
  acc: { list: [{ id, c, s, n, at }, …20], more: 37 },
  hr: [ …10 ],
  cut: { improve: 9, 'fast:coo:1': 63.0, hr: 12 }   // 第 10 名的分數：學生端算「再快 N 就上榜」
}
```
- 自己的分數**用本機 `NW` 算**（`NW.best`：§2.8），跟 `cut` 比，所以學生端只讀 1 份文件。

## 3. 2b 鐵匠鋪＋倉庫

### 3.1 為什麼好玩、一節課怎麼走

**好玩在哪**（MDA 的「美學」倒推，研究 §1.1）：
- **表現**：穿上咕咕帽，村莊裡、戰鬥裡、人物卡上的自己都戴著那頂帽子。GDD §15.5「穿什麼，就長什麼樣子」。
- **勝任**：同一隻炎牙狼，上週打不贏，做了裝備這週打贏了；強化 +1 馬上看得到數字變大（研究：SDT 勝任感）。
- **自主**：先做帽子還是先強化武器？要打咕咕鳥拿絨毛還是打泡泡蛙拿蛙皮？自己決定（研究：SDT 自主）。
- **驚喜但可預期**：圖紙是「有機會掉」，但有保底（§3.5）；顏色由放進去的材料決定，看得到（GDD §12.2）。

**打字還是核心**（研究：Habgood & Ainsworth 的內在整合，§1.1）：裝備一律是**乘法**——打錯的字照樣 0 傷害，攻擊力只放大「打對的字」。防具不會幫你打字，只讓你在三線戰鬥裡多一點容錯。

**核心循環**
```
委託板打怪 ──► 結算：材料、圖紙（「還差 1 個柔軟絨毛就能做咕咕帽！」）
    ▲                     │
    │                     ▼
 打得動更難的 ◄── 鐵匠鋪：打造（新的一件）／強化（+1）
 （炎牙狼 ★5）              │
    ▲                     ▼
    └──── 角色變強（攻擊力、生命…）＋變帥（帽子、盔甲顏色）
```

**一節課（40 分鐘，學生實際玩約 15～20 分鐘）**
| 時間 | 做什麼 |
|---|---|
| 0:00 | 進村。鐵匠鋪屋頂冒煙＋「！」（**只有真的能做東西時才亮**，研究：紅點只標要處理的，§3.1） |
| 0:30 | 進鐵匠鋪做一件（≤ 90 秒：選圖紙 → 打造 → 穿上） |
| 2:00 | 第 1 場狩獵（約 2～4 分鐘） |
| 6:00 | 結算畫面直接寫「鐵匠鋪：現在可以做 1 件」或「還差 2 個蛙皮」——**獎勵在結算當場看到，不要求課後再回來**（研究 §1.2） |
| 7:00 | 回鐵匠鋪強化 +1（≤ 30 秒）→ 第 2 場 |
| 下課 | 留一個下週的目標：「再 1 張圖紙」「再 2 個炎牙」 |

### 3.2 裝備五格與效果

**一格一個數字**（GDD §2.1「畫面只顯示一個數字」）。效果都直接接到三線戰鬥：

| 格 | 學生看到的 | 戰鬥裡做什麼（`nw-battle.js`） | 灰 | 綠 | 藍 | 每 +1 | 2b 最高（藍 +5） |
|---|---|---|---|---|---|---|---|
| 武器 | **攻擊力** | `hitMonster` 傷害 × 攻擊力 ÷ 100 | 100 | 108 | 116 | +2 | 126 |
| 頭盔 | **生命 +N** | `S.me.max = BAL.playerHp + N` | +10 | +20 | +30 | +2 | +40 |
| 盔甲 | **受傷少 N%** | 魔物招式的傷害 × (1 − N%)（不含亂打反擊 `wrongHit`、不含燃燒中毒） | 4% | 7% | 10% | +1% | 15% |
| 護手 | **舉盾多 N 秒** | Alt 舉盾 1.5 秒 → 1.5 + N | 0.2 | 0.3 | 0.4 | +0.04 | 0.6 |
| 護腳 | **紅線早 N 秒出現** | `buildStrikes` 的 `warn` 提早 N 秒（出手時間不變，等於多 N 秒反應） | 0.10 | 0.20 | 0.30 | +0.03 | 0.45 |

- **屬性**（只有藍色武器才有，GDD §12.3）：打「怕」這個屬性的魔物傷害 ×1.2，打「不怕」的 ×0.85（`MONSTERS[mk].fear／resist`，戰鬥現在沒用到這兩欄）。2b 只有炎牙刀（火）：咕咕鳥、跳跳菇怕火，泡泡蛙不怕火。委託單上已經寫怕什麼，學生第一次有理由「換武器打」。
- 屬性的狀態（燃燒魔物）留到第 3 段：魔物身上的狀態是新系統。
- **戰力**（一個數字比「我變強了嗎」，GDD §15.3）：每件 灰 10／綠 20／藍 30，每 +1 再 +2，五格加總。沒穿＝0；初心武器＝10。

- **為什麼數字比 GDD §14.12 小**（灰 100 → 藍 170）：現在的魔物血量（`HP_TIER`、`monMaxHp`）是在「沒有裝備」時調的，草原、森林照 GDD 的數字會直接被打穿（§3.4 的模擬）。GDD 的大數字留給第 3 段之後的新區域重算。

### 3.6 打造、強化、分解

**打造**
- 要：學會的圖紙＋材料＋字元。不夠時按鈕灰、寫「還差 2 個柔軟絨毛」「還差 30 字元」＋進度條（GDD §16.1）。
- **一定成功**。做出來的那件 +0，跳「打造完成！」（像 `showGift` 的大圖＋0.9 秒敲三下的動畫，研究：juice，§4.1），問「要穿上嗎？[穿上] [先放背包]」。比現在穿的好（戰力高）時「穿上」是金色。

**強化（+1～+5）**
- **一定成功、不會掉級、不會壞**（GDD §2.1 第 5 條「不懲罰嘗試」）。理由：
  - 兒童遊戲的失敗代價要低，孩子才敢試（研究：Gee 的「降低失敗代價」，§1.1）。
  - 「可能失敗、失敗會掉等」的強化，本質是讓人一直投入的隨機獎勵，正是兒童保護指引在擋的操縱性設計（研究：vzbv 2025、ICO，§2.1；把它套到強化上是經驗判斷）。
  - 一週只有一節課，一次失敗就等於白費一週。
- 成本（每 +1；字元 × 顏色倍率：灰 1、綠 2、藍 3）：

| 強化到 | +1 | +2 | +3 | +4 | +5 | 灰色 +0→+5 合計 | 綠 | 藍 |
|---|---|---|---|---|---|---|---|---|
| 字元 | 20 | 35 | 55 | 80 | 110 | 300 | 600 | 900 |
| 材料（同色以上任意） | 1 | 1 | 2 | 2 | 3 | 9 灰 | 9 綠 | 9 藍 |

- 用「同色以上的任意材料」：灰材料一直堆，這是它的主要用途（排水口，§3.8）。
- 外觀：+3 起花邊變成那件的顏色、+5 花邊變金色並在人物卡上閃一下（GDD §13.3「+5 邊框開始發光」）。
- 2b 上限 +5，畫面寫「+6 以上要等之後開放」。

**分解**
- 不要的裝備（沒穿的）→ 拿回打造材料的一半（無條件捨去，至少 1 個），**不退字元**、強化用掉的不退。
- 確認視窗：「分解後就不見了，會拿回：咕咕羽毛 ×2」，要按兩次。
- 不能分解：穿著的、初心武器、測試者之刃這類老師送的武器。

### 3.7 倉庫
- **不另外做全螢幕頁面**（UI-ART-SPEC §4：新的個人資料加分頁）。倉庫建築打開的就是背包，停在「📦 材料」分頁，多了倉庫的功能：
  - 材料、圖紙、**🛡 裝備**（新分頁：所有做出來的裝備，4 欄格子，顏色邊框＋右上角小點＋右下角 +N）。
  - 每格點一下：一句說明、「哪裡掉：草原的咕咕鳥」、「可以做：咕咕帽、羽毛護手」。
  - 排序：顏色高到低（預設）／種類／最新（GDD §15.4）。
  - 圖紙分頁：學會的亮、沒學會的灰並寫「咕咕鳥有機會掉」（讓孩子知道還有什麼可以收集）。

## 7. 參考做法（引用 `research/GAME-DESIGN-REFS.md`）

| 研究怎麼說 | 用在哪 |
|---|---|
| SDT：自主、勝任、連結預測樂趣與續玩（§1.1） | 進步榜預設打開；裝備可以自己選先做哪件（§2.1、§3.1） |
| MDA：先決定玩家感受，再回推機制（§1.1） | §2.1、§3.1 先寫「想讓孩子感受到什麼」 |
| 內在整合：學習內容就是核心機制（Habgood & Ainsworth，§1.1） | 裝備只放大「打對的字」，不取代打字（§3.1） |
| Gee：失敗代價要低、愉快的挫折（§1.1） | 強化一定成功（§3.6） |
| 低名次被打擊；相對／分程度的榜較不傷人（arXiv 2305.08346、NSF，§2.1） | 分年級、前 10＋自己、榜外不顯示名次、下降不顯示、神準改名單（§2.2、§2.3） |
| 客戶端分數不可信，重要名次人審（Supercraft、Bugnet，§2.1） | 老師端彙總、重算、新的前 3 名先給老師看（§2.7） |
| 限時／天天登入壓力對兒童有風險（ACM、vzbv、ICO，§2.1） | 不倒數、不做每日登入、榜單每週更新但錯過不會失去什麼（§2.1、§3.8） |
