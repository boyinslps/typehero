## 1. 開放方式：2a、2b 分開開

### 1.1 為什麼分開、順序
- `rank`、`forge`、`storage` 現在都是 `wip: 2`，`buildingOpen()` 用 `parseFloat(b.wip) <= openStage()`，**沒辦法只開其中一個**。
- **先開 2b，同時開始寫 `mg_nw_runs`；至少 4 週後再開 2a**（§8 第 1 題）。
  - 「進步」要比「兩週以前」與「最近兩週」，兩邊同一個題目等級**各至少 3 場**（§2.2）。一週一節、一節 2 場，最快也要 4 週才湊得到兩邊。
  - 不選「這一週比以前」：一週只有 2 場，湊不到 3 場，等於回到 v1「最好 1 場」的運氣問題。
  - 先有裝備再開最快討伐榜，榜才不會被「裝備出來前」的舊紀錄卡住（經驗判斷）。
  - 鐵匠鋪是孩子等最久的（鐵匠 NPC 一直說「快好了」）。
- 寫 `mg_nw_runs` 要新規則（§2.6），所以 **2b 上 main 之前老師要先貼一次規則**；2a 開的時候不用再貼。

### 1.2 程式改法
```js
// nw-data.js：段號改成字串，開了哪幾段用清單表示（可以跳著開）
export const OPEN_STAGES = ['1'];                 // 開 2b → ['1','2b']；再開 2a → ['1','2b','2a']
export const openStages = () => (location.hostname === 'localhost' && window.__NW_STAGES__) || OPEN_STAGES;
export const stageOpen = s => openStages().includes(String(s));
export const buildingOpen = b => !!b.act && (!b.wip || stageOpen(b.wip));
```
- `VILLAGE.buildings`：`rank` → `wip: '2a'`；`forge`、`storage` → `'2b'`；`rooms` 維持 `'3a'`；`shop`、`armor` → `'3b'`；`star` → `'5'`。
- 舊的 `OPEN_STAGE`／`openStage()` 刪掉；測試用的 `window.__NW_STAGE__` 改成 `__NW_STAGES__`（陣列），`tools/browser-test/` 一起改。
- 「鐵匠鋪開張就能用」這類句子改看 `stageOpen('2b')`。`RELEASE-STAGES.md` 的「怎麼開下一段」同步改。

### 1.3 退回
- 從 `OPEN_STAGES` 拿掉那個字串、重新發版。**資料不刪**。2b 收回時，戰鬥照常套用已經穿的裝備（不然孩子會覺得被沒收），只是進不了鐵匠鋪。
- 2a 收回：榮譽碑變回施工中；`mg_nw_runs` 照寫。

## 2. 2a 榮譽碑

### 2.1 設計目標（先想要孩子感受到什麼，再回推規則；研究：MDA，§1.1）
1. **「我變厲害了」被看見**（勝任感，研究：SDT §1.1）。所以預設打開「進步」，跟自己比。
2. **排在後面的孩子不會難過**：低名次會打擊動機，相對、分程度的榜比較不傷人（研究：arXiv 2305.08346、NSF 相對榜研究，§2.1）。所以只列前 10＋自己、榜外不顯示第幾名、分年級、只顯示往上的變化。
3. **亂打的人上不了榜**：第 2、3 道防線（GDD §20.3～20.4）。客戶端算的分數不可信，可疑的交給人看（研究：Supercraft／Bugnet，§2.1）。
4. **不造成「怕錯過」**：沒有倒數、沒有「本週最後機會」（研究：ACM／vzbv／ICO，§2.1）。

### 2.2 三個分頁

| 分頁（照畫面順序） | 比什麼 | 為什麼這樣定 | 進榜門檻 |
|---|---|---|---|
| 🌱 **進步**（預設打開） | 同一個**題目等級**裡，「最近兩週最好 3 場的打字速度平均」比「兩週以前最好 3 場的平均」快幾 %；顯示「打字變快 18%」 | 跟自己比，每個人都有機會。用打字速度不用討伐秒數：**裝備不影響它** | 同一個題目等級，兩邊各至少 3 場合格場次 |
| ⚡ **最快討伐** | 選魔物＋星級，最快秒數（只算打贏） | GDD §20.1「技術與配裝」：**配裝也算**，名字旁邊標武器圖示和戰力 | 那一場正確率 ≥ 90% |
| 🎯 **神準名單** | 最近 10 場 Lv10 以上的合格場次，平均正確率 ≥ 97% 就上名單。**不排名次** | 真實資料正確率中位數 100%（GDD §3.1），排名次會幾十人並列；改成里程碑，跟抓蟲徽章同一個思路 | 10 場（約 5 節課）。GDD 原本寫 Lv20 以上，但森林最高 Lv22，只有 ★5 夠，改 Lv10 |

**「進步」怎麼算**（審查指出 v1 兩個問題，照改）：
- **題目等級**＝`題目字數上限 × 詞庫難度`。字數上限看星級（`MAX_CHARS`，`nw-data.js:113`：★1～2 是 4 字、★3～4 是 6 字、★5 是 8 字）；詞庫看魔物等級（`nw-battle.js` 的 `tierIdx`：Lv < 10、< 20、其他）。程式寫成 `qBand(star, lv)`，例 `'4:0'`。**刷容易的星級不會讓速度變高**，因為只跟同一個等級的自己比。
- 兩邊都用「最好 3 場的平均」：v1 用「最近最好 1 場」比「以前最好 3 場」，本身就偏高，打越多場越容易靠運氣上榜。兩邊對稱就沒有這個偏差。
- 一個人有好幾個題目等級都達標時，取進步最多的那一個，榜上寫是哪一級（「★3～4 題目」）。這會留一點「多選一」的運氣成分，可以接受（經驗判斷）。
- 打字速度＝打對的字 ÷ 各題作答時間加總 × 60（`cpm`，§2.5）。
- 進步超過 60%：照樣上榜，教師頁標 ⚠；超過 100%：先不上榜，列在教師頁待看（初學者一開始進步很快，不能一律擋）。

**為什麼刪掉獵人等級、圖鑑**
- 獵人等級：一週一節課，比的幾乎就是出席次數；而且 HR 存在誰都能改的 `mg_scores`。
- 圖鑑：現在只有 4 隻魔物，一兩節課就全打過，大家並列。之後魔物變多再考慮。

**分年級**：四、五、六年級各一張榜（§8 第 3 題）。四年級跟六年級手速差很多，放一起四年級永遠上不了榜（經驗判斷；研究：相對榜，§2.1）。

### 2.3 顯示規則（三個分頁共用）
- 列：`名次徽章（前 3 名金銀銅，PX.badge）｜504・5號｜名字｜分數`。名字＝`displayName(mg_scores.name)`（v3.14.1 起是登入名字）；老師用 `mg_bugboard.hideNick` 隱藏的人顯示「神秘獵人」。**名字在彙總時就寫好**（§2.7），學生端不另外讀。
- **前 10 名＋自己**。自己在前 10 就把那一列框金色。
- **自己不在前 10：不顯示第幾名**，只寫差多少：
  - 進步：「再快 3% 就上榜！」
  - 最快：「再快 4.2 秒就上榜！」
  - 還沒有合格紀錄：寫怎麼拿（「同一種星級再打 2 場，正確率 90% 以上，就會有進步紀錄」）。
- **比上週**：名字右邊只顯示 **▲3** 或 **🆕 新上榜**；**下降不顯示**（經驗判斷：▼5 只是公開說你退步了）。
- 神準名單：顯示最近達標的 20 人（新的在前）＋「還有 N 人也很準！」；自己沒達標寫「最近 10 場平均 95%，到 97% 就上名單」或「Lv10 以上再打 4 場」。
- 頂端小字：「榮譽碑每週更新，上次：11 月 18 日」。自己最新的紀錄比榜上好時寫「老師下次更新就會算進去」。

### 2.4 第二道防線：進榜條件（GDD §20.3）
一場要**同時**符合才是「合格場次」：
1. `res.valid`（打贏或答 ≥ 3 題）。
2. **正確率 ≥ 90%**（`RANK_MIN_ACC = 0.9`）。
3. **有寫進 `mg_nw_runs`**（只看那一筆，所以速度、正確率、時間一定來自同一場）。
4. 沒有被第三道標記，或已經被老師按「沒問題」。
5. 不在老師的「先不上榜」名單（§2.10）。

不合格的場次照樣拿掉落、經驗、字元。結算畫面（`showResult`）多一行：
- 正確率不到：「這場正確率 82%，要 90% 才會上榮譽碑喔」。
- 被標記：「這場紀錄要等老師看過才會上榮譽碑」。**不寫「作弊」「可疑」**（GDD §20.4）。
- 合格且破了自己的紀錄：「🏆 新紀錄！下次榮譽碑更新就會算進去」。

### 2.5 第三道防線：可疑紀錄偵測（GDD §20.4，先做 4 種）

戰鬥中多記的東西（`nw-battle.js`，在本機算，結束時放進 `res`）：
- 每題：字數、按鍵數、作答毫秒、打對幾個字 → `q: [[字數, 按鍵, 毫秒, 對], …]`（最多 120 題）。
- 按鍵數：輸入框的 `keydown`，算一般字鍵、Backspace、`e.key === 'Process'`、`e.key === 'Unidentified'`、`e.keyCode === 229`（注音輸入法組字、部分瀏覽器與觸控鍵盤會送這些）；不算 Enter、Esc、Ctrl、Alt、Shift（Ctrl／Alt 是換線與舉盾）。
- `act`＝各題作答時間加總（秒）；`cpm`＝打對的字 ÷ `act` × 60。

| 代碼 | 老師頁顯示（學生看不到） | 判斷 | 抓什麼 |
|---|---|---|---|
| `keys` | 按鍵太少 | 打對的字數 > 按鍵數 ÷ 1.5（整場打對 ≥ 20 字才判斷；注音一個字至少 2 鍵）。**整場 0 個按鍵不判斷**（觸控裝置有些不送 keydown），只在紀錄記 `nokey: 1` | 貼上、外掛輸入 |
| `fast` | 太快 | 任一題（≥ 3 字）每秒超過 5 字，或整場 `cpm` > `CPM_SANE`（暫定 130 字/分：舊世界全校最快 85 字/分 × 1.5） | 異常速度 |
| `sum` | 數字對不起來 | 各題「對」加總 ≠ 整場打對字數，或題數 ≠ 已答題數，或各題毫秒加總 > 整場秒數 + 1 | 開主控台改數字 |
| `jump` | 進步太跳 | 這場 `cpm` > 自己同一題目等級前 5 場 `cpm` 中位數的 3 倍（有 5 場才判斷；存 `NW.cpmHist[qBand]`，各最多 5 個） | 換人代打 |

- **不做** `even`（節奏太平均，要存按鍵間隔、誤判難評估）與 `paste`（貼上本來就被擋了，`nw-battle.js:596`）。上線看資料後再決定要不要加。
- 門檻常數放 `nw-data.js` 的 `SUS`；**老師端彙總時用同一套函式重算**（§2.7），學生改了自己的程式也會在老師那邊被抓到。
- 被標記 → 寫 `mg_nw_flags/run_{runId}`（§2.6），老師按之前不上榜。標記**不刪、不罰、不扣獎勵**。
- 第一週老師頁列出所有被標的場次，誤判多就放寬（經驗判斷）。

### 2.6 `mg_nw_runs`：每場一筆

**什麼時候寫**：每一場 `res.valid` 的狩獵結束（`finishHunt` 之後），輸贏都寫（進步與神準名單要用輸掉場次的速度與正確率）。**2b 上線就開始寫**（§1.1），2a 開之前沒人讀。

```js
// mg_nw_runs/{文件ID}_{t}　例：五年級4班_5號_1763500000000（固定 ID：重送同一筆不會變兩筆）
{
  id: '五年級4班_5號',          // 跟 mg_scores 的文件 ID 一樣（index.html 的 seatDocId()）
  cls: '五年級4班', seat: 5, uid: request.auth.uid,
  t: 1763500000000,            // 本機時間，只拿來組 ID，不拿來分週
  ts: serverTimestamp(),       // 規則要求＝request.time；分週、分「兩週以前／最近兩週」一律用它
  v: 1, app: '3.15.0',
  mk: 'coo', rk: 'grass', star: 3, lv: 6, qb: '6:0', res: 'win', secs: 84.2,
  acc: 0.957, ans: 31, cor: 88, typ: 92, keys: 214, nokey: 0, act: 61.3, cpm: 86.1,
  fl: { fast: 0, paste: 0, wrong: 1 },   // 現有的 S.flags 照抄，給老師看
  sus: [],                     // §2.5 的代碼
  w: 'dagger', atk: 105, pw: 45, tier: 'B',
  q: [[2, 5, 2100, 2], …]
}
```
- 大小：一場約 1～2 KB；全校一週約 600 場 ≈ 1 MB，一學期十幾 MB，免費額度內。
- **寫不進去（離線、逾時）**：放進 `NW.runQ`（最多 5 筆，多的丟最舊的），下次進村或下一場結束時補寫。補寫的 `ts` 是補寫當下，所以那場算進「補寫的那一週」，這是故意的（改電腦時間塞不了舊紀錄）。
- **重送**：學生**不能 update**。同一個 ID 再寫一次會被規則擋（permission-denied）；ID 含自己的文件 ID 與毫秒時間，別人不會剛好寫到同一個，所以**重送遇到 permission-denied 就當作已經寫進去**，從 `runQ` 拿掉（跟換名紀錄 `writeNameFlag` 同一招）。
- 被標記時另寫：`mg_nw_flags/run_{runId}` `{ type:'run', status:'pending', docId, cls, seat, name, runId, why:[…], mk, star, t }`。

**規則**（`firestore-rules.txt`；`tools/rules-test/` 補案例；**2b 上 main 前老師先備份再貼**）：
```
match /mg_nw_runs/{run} {
  allow read: if isTeacher();            // 學生端不讀紀錄（榜單讀 mg_nw_board）
  allow create: if signedIn()
    && request.resource.data.keys().hasOnly(['id','cls','seat','uid','t','ts','v','app','mk','rk','star','lv','qb','res',
         'secs','acc','ans','cor','typ','keys','nokey','act','cpm','fl','sus','w','atk','pw','tier','q'])
    && request.resource.data.uid == request.auth.uid
    && request.resource.data.ts == request.time
    && run.matches(request.resource.data.id + '_[0-9]+')
    && request.resource.data.secs is number && request.resource.data.secs >= 0 && request.resource.data.secs <= 310
    && request.resource.data.acc is number && request.resource.data.acc >= 0 && request.resource.data.acc <= 1
    && request.resource.data.star is int && request.resource.data.star >= 1 && request.resource.data.star <= 5
    && request.resource.data.q is list && request.resource.data.q.size() <= 120
    && request.resource.data.sus is list && request.resource.data.sus.size() <= 4;
  allow update, delete: if isTeacher();  // 學生不能改：不然可以把舊紀錄的 ts 刷成最近，灌進步榜
}
match /mg_nw_flags/{flag}：type 清單加 'run'，欄位清單加 'runId'、'why'（why 是 list、size() <= 4）
match /mg_nw_board/{doc}         { allow read: if signedIn(); allow write: if isTeacher(); }
match /mg_nw_board_private/{doc} { allow read, write: if isTeacher(); }
```
- 現行規則 `mg_nw_runs` 是「登入者都能讀、都能新增」；改成只有老師讀，紀錄裡有每題時間，同學沒必要看（經驗判斷）。
- `uid` 是匿名登入的 uid，**不是身分驗證**。電腦教室的還原卡讓每次開機都是新的 uid，所以「一個座號出現很多 uid」是正常的，**先不拿來標記**；只存著，兩週後看資料再決定有沒有用。

### 2.7 榜單資料從哪裡來：老師端彙總（`mg_nw_board`）

**誠實說**：學生能寫任何人的 `mg_scores`、能用主控台寫出「看起來合理」的 `mg_nw_runs`。純前端只能**提高作弊成本、讓老師看得到**，做不到不可能（研究：客戶端分數不可信，§2.1；SPEC-TEACHER-ADMIN §1.1）。所以榜單不讓學生端算，而是**老師端彙總，寫成只有老師能寫的文件**：

```
學生打一場 ──► mg_nw_runs（只能新增、ts 是伺服器時間、不能改）
          └─► 被標記 ──► mg_nw_flags/run_…（只有老師讀）
老師登入（舊控制台或管理頁）──► teacher/rank-calc.js 讀「上次之後的新紀錄」（where ts > 游標）
                    ├─ 用同一套 SUS 函式重算
                    ├─ 排除：待審核、不採計、先不上榜名單
                    ├─ 更新每個學生的累積狀態（mg_nw_board_private/{年級}）
                    └─ 寫 mg_nw_board/{年級}（學生只讀這一份）
```

| 資料 | 在哪 | 誰寫 | 學生改得了嗎 | 怎麼辦 |
|---|---|---|---|---|
| 每場紀錄 | `mg_nw_runs` | 學生（只能新增） | 能偽造新的，改不了舊的 | 老師端重算 SUS；⚠ 比合理下限快（`FASTEST_FLOOR` 依攻擊力換算）、進步 > 60%；老師看到再移除 |

| 裝備、字元 | `mg_scores.nw` | 學生 | 能 | 只能抽查（教師頁學生卡看得到裝備與場數）；自動 ⚠ 等有資料再做 |

- **新的前 3 名不用等老師**：審查認為每週要老師多按是負擔，而且被偵測標記的本來就會進待審。其他有問題的，老師在 🏆 分頁移除（§2.10）。

**什麼時候更新**（§8 第 2 題）：
- **舊控制台老師登入成功後**（`index.html` 的 admin app，每節課開戰本來就會登入）：上次更新超過 6 小時就在背景跑一次（動態 import `teacher/rank-calc.js`，失敗不擋開戰）。
- `teacher.html` 打開「總覽」時同樣檢查；🏆 分頁有「現在更新」。
- 「比上週」：每次更新存名次；用 `ts` 換成台灣時間的第幾週（`twWeek = floor((twDay(ts) + 3) / 7)`，週一開始），跨週後第一次更新把上週最後的名次搬到 `prev`。
- 老師很久沒登入 → 榜單停在上次，頂端寫更新日期。**榜單慢一點，換來學生改不到榜**。

## 3. 2b 鐵匠鋪＋倉庫

### 3.1 為什麼好玩、一節課怎麼走

**好玩在哪**（MDA 的美學倒推，研究 §1.1）：
- **表現**：穿上咕咕帽，村莊、戰鬥、人物卡上的自己都戴著那頂帽子（GDD §15.5）。
- **勝任**：強化 +1 馬上看得到數字變大；同一隻魔物打得更快（研究：SDT 勝任感）。
- **自主**：先做帽子還是先強化武器？要打咕咕鳥拿絨毛還是打泡泡蛙拿蛙皮？自己決定（研究：SDT 自主）。
- **驚喜但可預期**：圖紙「有機會掉」，但有保底（§3.5）；做出來的顏色看得到（GDD §12.2）。

**打字還是核心**（研究：Habgood & Ainsworth 的內在整合，§1.1）：裝備一律是**乘法**，打錯的字照樣 0 傷害，攻擊力只放大「打對的字」。防具不會幫你打字，只讓你在三線戰鬥裡多一點容錯，而且**只對會攻擊的魔物有用**（§3.2）。

**核心循環**
```
委託板打怪 ──► 結算：材料、圖紙（「還差 1 個柔軟絨毛就能做咕咕帽！」）
    ▲                     │
    │                     ▼
 打得更快、更穩 ◄── 鐵匠鋪：打造（新的一件）／強化（+1）
    ▲                     │
    └──── 角色變強（攻擊力、生命…）＋變帥（帽子、盔甲顏色）
```

**一節課（40 分鐘，學生實際玩約 15～20 分鐘）**
| 時間 | 做什麼 |
|---|---|
| 0:00 | 進村。鐵匠鋪屋頂冒火花＋「！」（**只有真的能做東西時才亮**，研究：紅點只標要處理的，§3.1） |
| 0:30 | 進鐵匠鋪做一件（≤ 90 秒：選圖紙 → 打造 → 穿上） |
| 2:00 | 第 1 場狩獵（約 2～4 分鐘） |
| 6:00 | 結算畫面直接寫「鐵匠鋪：現在可以做 1 件」或「還差 2 個蛙皮」——**獎勵在結算當場看到**（研究 §1.2） |
| 7:00 | 回鐵匠鋪強化 +1（≤ 30 秒）→ 第 2 場 |
| 下課 | 留一個下週的目標：「再 1 張圖紙」「再 2 個炎牙」 |

### 3.2 裝備五格與效果

**一格一個數字**（GDD §2.1）。效果直接接到三線戰鬥：

| 格 | 學生看到的 | 戰鬥裡做什麼（`nw-battle.js`） | 灰 | 綠 | 藍 | 每 +1 | 2b 最高（藍 +5） |
|---|---|---|---|---|---|---|---|
| 武器 | **攻擊力** | `hitMonster` 傷害 × 攻擊力 ÷ 100 | 100 | 105 | 110 | +2 | 120 |
| 頭盔 | **生命 +N** | `S.me.max = BAL.playerHp + N` | +10 | +20 | +30 | +2 | +40 |
| 盔甲 | **受傷少 N%** | 魔物招式傷害 × (1 − N%)（不含亂打反擊 `wrongHit`、燃燒、中毒） | 4% | 7% | 10% | +1% | 15% |
| 護手 | **舉盾多 N 秒** | Alt 舉盾 1.5 秒 → 1.5 + N | 0.2 | 0.3 | 0.4 | +0.04 | 0.6 |
| 護腳 | **紅線早 N 秒出現** | `buildStrikes` 的 `warn` 提早 N 秒（出手時間不變，等於多 N 秒反應） | 0.10 | 0.20 | 0.30 | +0.03 | 0.45 |

- **屬性**（只有藍色武器有，GDD §12.3）：打「怕」這個屬性的魔物 ×1.1、「不怕」的 ×0.9（`MONSTERS[mk].fear／resist`，戰鬥現在沒用到）。2b 只有炎牙刀（火）：咕咕鳥、跳跳菇怕火，泡泡蛙不怕火。**武器＋屬性合起來最高 ×1.32**（120 × 1.1），理由見 §3.4 的 G1。
- **防具只對會攻擊的魔物有用**：現行 `ATTACKS_OPEN`（`nw-data.js:110`）只有咕咕鳥（單線、夾擊）與泡泡蛙（重壓）會攻擊，跳跳菇、炎牙狼不攻擊。所以：
  - 頭盔、盔甲、護腳在咕咕鳥、泡泡蛙身上有用；護手只對泡泡蛙的重壓有用（舉盾）。
  - 鐵匠鋪的防具說明、委託單、公告都寫「對會攻擊的魔物才有用」，並**從 `ATTACKS_OPEN` 自動列出**現在是哪幾隻（例：「現在會攻擊的：咕咕鳥、泡泡蛙」），之後開放更多攻擊就自動更新，不會寫錯。
  - 炎牙狼要不要跟 2b 一起開攻擊：**預設不一起開**，先用升級後的模擬器驗證（§3.4、§8 第 5 題）。
- **戰力**（一個數字比「我變強了嗎」，GDD §15.3）：每件 灰 10／綠 20／藍 30，每 +1 再 +2，五格加總。初心武器＝10。
- 測試者之刃（`GIFT_WEAPONS.testblade`，原本傷害 ×1.12）：轉成一件「綠色、攻擊力 112」的武器（比一般綠色高，維持測試者的獎勵感），可以用綠材料強化，上限一樣算進 ×1.32 的檢查；連環斬 4 題一次照舊。
- **為什麼數字比 GDD §14.12 小很多**（灰 100 → 藍 170）：現在的魔物血量（`HP_TIER`、`monMaxHp`）是在沒有裝備時調的，照 GDD 的數字快的孩子會跳過三線戰鬥（§3.4 G1）。GDD 的大數字留給第 3 段之後的新區域重算。

`nw-data.js` 新增純函式（戰鬥、人物卡、教師頁共用，node 可測）：

gearLook(nw)  → { helm, helmC, armor, trim, hands, boots, weapon, wfx }   // 給 heroLook 的 gear 參數

新增 `tools/nw-sim/gear.mjs`：輸出「6 個樣本學生 × 裝備組合（無、灰全身、綠全身 +3、綠全身 +5、藍武器 +5）× 魔物（咕咕鳥★1、泡泡蛙★3、咕咕鳥★5、炎牙狼★1、炎牙狼★5）× 兩種攻擊設定」的勝率、平均秒數、倒下次數、每場看到幾次攻擊、閃避／防禦成功率。

**用現在的模擬器（舊模型）粗跑的結果**（2026-11-19；武器用「魔物血量 ÷ 倍率」近似；「不攻擊」用「魔物傷害降到最低、學生不做閃避」近似）：

*A. 現行：炎牙狼不攻擊*
| 學生樣本 | 炎牙狼★1 無裝備 → 武器 ×1.11 → ×1.15 | 炎牙狼★5 無裝備 → ×1.15 |
|---|---|---|
| 四年級・慢（12 字/分） | 73% → 80% → 84% | 53% → 55% |
| 五年級・慢（11 字/分） | 81% → 87% → 90% | 40% → 48% |
| 四年級・中（20 字/分） | 100%（191 秒 → 167 秒） | 89% → 98%（253 秒 → 233 秒） |
| 五年級・快（41 字/分） | 100%（122 秒 → 103 秒） | 100%（170 秒 → 148 秒） |

*B. 舊模型：所有魔物都攻擊（v1 的數字，只是參考）*：四年級・中 炎牙狼★5 無裝備 8%、綠全身 +3 67%。

*C. 最快樣本（五年級・快）咕咕鳥★1 平均秒數*：無裝備 89 秒、×1.15 71 秒、**×1.32 61 秒**、×1.35 56 秒（v1 那次跑）。

看到的事：
1. **現行遊戲裡，裝備的效果主要是「打得快一點」和「慢的孩子炎牙狼★1 多贏 7～11 個百分點」**，不是 v1 寫的「打不贏 → 打得贏」。中等速度的孩子沒裝備也打得贏炎牙狼★5（89%）。
2. 「裝備沒跟上就打不過」（GDD §1.4）要等炎牙狼也攻擊才會出現（B），而 B 的「8%」代表沒裝備的孩子會突然卡關。**所以炎牙狼的攻擊不跟 2b 一起開**，等新模擬器在「狼也攻擊」下跑出合理勝率、而且大部分人已經有一兩件裝備後再開（§8 第 5 題）。
3. **慢的孩子主要是時間到才輸**，裝備幫不了太多，那是難度層級 `HP_TIER` 的事（經驗判斷）。
4. 快的孩子會被加速太多：×1.35 時 56 秒，魔物來不及出幾招。所以上限壓到 ×1.32（61 秒）。

**驗收範圍**（新模擬器，6 個樣本、每格 300 場；不在範圍內就改 §3.2 的數字，不改驗收）。**G2、G3、G6 必須在「現行」攻擊設定下達標**：

| # | 驗收 | 範圍 |
|---|---|---|
| G1 | 戰鬥不會被裝備跳過（**含屬性**） | 任何樣本、任何裝備（含炎牙刀藍 +5 打怕火的咕咕鳥，×1.32）：草原 ★1 平均 ≥ 55 秒；會攻擊的魔物每場至少 2 次攻擊。不過就再壓武器每 +1 的加成（改 +1.5），不再降屬性 |
| G2 | 變強看得到（現行） | 「四年級・中」綠武器 +5 比無裝備：炎牙狼★5 討伐時間少 ≥ 7%；武器每 +1 討伐時間少 1%～2.5% |
| G3 | 慢的孩子有幫助（現行） | 兩個「慢」樣本：綠全身 +3 的炎牙狼★1 勝率多 ≥ 5 個百分點；咕咕鳥★5 的倒下次數少 ≥ 30% |
| G4 | 還是要練打字 | 兩個「慢」樣本：全身綠 +5 的炎牙狼★5 勝率 ≤ 60%（兩種攻擊設定都要） |
| G5 | 不做裝備也能玩 | 沒有裝備的人，草原 ★1～★3 勝率不變（不動魔物血量） |
| G6 | 防具看得到差別（現行） | 「慢」樣本：綠護腳 +3 讓咕咕鳥的閃避成功率多 ≥ 10 個百分點；綠護手 +3 讓泡泡蛙重壓的防禦成功率多 ≥ 10 個百分點 |

| G8 | 狼要不要攻擊（給 §8 第 5 題） | 「狼也攻擊」設定下，「四年級・中」**無裝備**炎牙狼★5 勝率 ≥ 50%、灰全身 ≥ 65%，才建議開；不到就調狼的傷害或先只開一招 |

### 3.6 打造、強化

**打造**
- 要：學會的圖紙＋材料＋字元。不夠時按鈕灰、寫「還差 2 個柔軟絨毛」「還差 30 字元」＋進度條（GDD §16.1）。
- **一定成功**。做出來是 +0，跳「打造完成！」（敲三下 0.9 秒的動畫，研究：juice，§4.1），問「要穿上嗎？[穿上] [先放背包]」。戰力比現在穿的高時「穿上」是金色。
- **裝備最多 60 件**（一件約 60 位元組，存檔大小的保險）。到上限時打造按鈕寫「裝備已經 60 件了，之後開放『分解』就能整理」。13 種配方要做到 60 件很難，第 3 段開分解前應該頂得住。

**強化（+1～+5）**
- **一定成功、不會掉級、不會壞**（GDD §2.1 第 5 條）。理由：
  - 兒童遊戲的失敗代價要低，孩子才敢試（研究：Gee，§1.1）。
  - 「可能失敗、會掉等」的強化是讓人一直投入的隨機獎勵，正是兒童保護指引在擋的操縱性設計（研究：vzbv 2025、ICO，§2.1；套到強化上是經驗判斷）。
  - 一週一節課，一次失敗等於白費一週。
- 成本（每 +1；字元 × 顏色倍率：灰 1、綠 2、藍 3）：

| 強化到 | +1 | +2 | +3 | +4 | +5 | 灰 +0→+5 合計 | 綠 | 藍 |
|---|---|---|---|---|---|---|---|---|
| 字元 | 20 | 35 | 55 | 80 | 110 | 300 | 600 | 900 |
| 材料（同色以上任意） | 1 | 1 | 2 | 2 | 3 | 9 灰 | 9 綠 | 9 藍 |

- 用「同色以上的任意材料」：灰材料一直堆，這是它的主要去處（§3.8）。
- 外觀：+3 起花邊變那件的顏色、+5 花邊變金色並在人物卡上閃一下（GDD §13.3）。
- 2b 上限 +5，畫面寫「+6 以上要等之後開放」。

### 3.10 資料結構與舊存檔

```js
nw: {
  gearV: 1,                              // 裝備資料版本：搬移只做一次
  gear: [ { id: 'g7k2', k: 'coo_hat', c: 'green', p: 2, t: 1763500000000 } ],
  eq: { weapon: 'g1a0', helm: 'g7k2', armor: null, gloves: null, boots: null },
  bp: ['bp_staff', 'bp_coo_hat', …],     // 不變
  mats: { coo_feather: 12, … },          // 不變
  bpDry: { coo: 2 },                     // 圖紙保底（§3.5）
  forge: { made: 3, ups: 4, top: 2, gift: 1 },
  best: { … }, cpmHist: { … }, runQ: [ … ]   // 2a 用（§2.6、§2.8）
}
```
- **舊存檔搬移**（`normalizeNw`，**只在 `gearV` 不是 1 時做**，做完設 `gearV = 1`）：
  1. 有 `starter` → 一件 `{ k: 'w_' + starter, c: 'gray', p: 0 }`。
  2. `gw` 裡每把老師送的武器 → 一件（`testblade` 綠色、攻擊力 112）。
  3. `eq.weapon`＝舊的 `equip` 指到的那件（`''`＝初心武器）。
  - 用旗標而不用「沒有 `gear` 就搬」：本機舊存檔（`localStorage`）比雲端新而被選中時，沒有 `gear` 會再搬一次，把做好的裝備換成只剩初心武器。`gearV` 是 1 但 `gear` 不見時**不重搬**，只放一把初心武器並 `console.warn`，老師可以用信件補（§3.12）。
- **舊欄位照寫**：`equip`、`gw` 存檔時從 `gear`／`eq` 推回去，還開著舊分頁的學生、教師頁舊程式不會壞。`curWeapon(nw)` 改成看 `eq.weapon` 那件的武器種類，**11 個呼叫點不用改**。
- 「前 3 場可以免費換初心武器」照舊：換的時候把那件初心武器的 `k` 換掉。
- **雙分頁**：打造、強化後用 `saveNwNow()` 立刻存；動作前重讀雲端存檔的 `savedAt`，比自己新就先重新載入（跟信箱領取同一招）。
- `mg_scores` 誰都能寫（SPEC-TEACHER-ADMIN §1.1），有了裝備後蓋掉同學存檔更有誘因；2b 不解這個洞，老師用信件補發。

- 戰鬥算出來的欄位（`nw-battle.js` 的 `res`，V2 沒開時只是多帶著，不影響結算）：
