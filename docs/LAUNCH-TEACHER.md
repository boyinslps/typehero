# 上線步驟（給老師）：教師管理頁、信箱、活動、佈告欄

> 給黃老師看的。照順序一步一步做就好，不用懂程式。
> 對應版本：v3.14.0。技術細節在 [`SPEC-TEACHER-ADMIN.md`](SPEC-TEACHER-ADMIN.md)，這份只講「按哪裡」。

## 先看這三件事

1. **找沒有課的時段做**（例如放學後、週末）。從第 3 步到第 4 步中間，學生的「序號、組隊房間、回報問題」會暫時壞掉，所以這兩步**中間隔越短越好**，一口氣做完。
2. **全部做完大約 30 分鐘**。第 1、2 步可以先做（不影響學生），第 3、4 步要連著做。
3. **第 4 步要老師說「可以上」才做**。在那之前，程式都還在開發分支，學生看不到任何改變。

準備好的東西：
- Firebase 主控台（專案 `school-4c9bf`）的登入權限。
- 一個你自己的 email（當老師登入帳號）和一組新密碼（建議 12 字以上，不要跟別的網站一樣）。
- 一個記事本（記下下面會複製的東西，不要貼到網路上、不要傳給別人）。

---

## 第 1 步：開「電子郵件／密碼」登入，建老師帳號（不影響學生，可以先做）

1. 打開 Firebase 主控台，選專案 `school-4c9bf`。
2. 左邊選 **Build（建構）→ Authentication（驗證）**。
3. 上面選 **Sign-in method（登入方式）**。
4. 找到 **Email/Password（電子郵件／密碼）**，點進去，把第一個開關打開（**Enable**），按 **Save（儲存）**。
   - 只要開第一個，「Email link（無密碼登入）」不用開。
   - 原本的 **Anonymous（匿名）** 登入**不要關**，學生靠它進遊戲。
5. 上面改選 **Users（使用者）**，按 **Add user（新增使用者）**。
6. 填你的 email 和密碼，按 **Add user**。
7. 清單裡會出現你剛建的帳號，旁邊有一長串 **User UID（使用者 UID）**。**按複製**，貼到記事本。下一步要用。

> 這個 UID 和 email 都**不要寫進 GitHub、不要貼進聊天**。

---

## 第 2 步：建 `mg_admins/{你的 UID}`（告訴資料庫「這個帳號是老師」）

**一定要在第 3 步之前做**，不然貼了新規則以後，你自己也被擋在外面。

1. 左邊選 **Build → Firestore Database**，上面選 **Data（資料）**。
2. 按 **Start collection（開始集合）**（如果左邊已經有 `mg_admins`，就直接點它，再按 **Add document**）。
3. **Collection ID（集合 ID）** 填：`mg_admins`，按 Next。
4. **Document ID（文件 ID）**：**不要按自動 ID**，把剛剛複製的 **UID 貼進去**（要完全一樣，不能多空白）。
5. 欄位：
   - Field（欄位）：`ok`
   - Type（類型）：`boolean`
   - Value（值）：`true`
6. 按 **Save（儲存）**。

檢查：資料裡看到 `mg_admins` → 一份以你的 UID 當名字的文件 → 裡面 `ok: true`。

---

## 第 3 步：先備份舊規則，再貼新規則並發布

> 第 3 步貼完規則的那一刻起，**舊版程式的序號、房間、回報、舊控制台會暫時壞掉**，直到第 4 步新程式上線。所以第 3、4 步要連著做。

1. 還在 **Firestore Database**，上面選 **Rules（規則）**。
2. **先備份**：在規則編輯框裡按 **Ctrl+A（全選）→ Ctrl+C（複製）**，貼到記事本，**存成檔案**（例如 `舊規則備份-日期.txt`）。這個檔案是出事時退回去用的，要留著。
3. 打開專案裡的 `firestore-rules.txt`（GitHub 上 `firestore-rules.txt` 點進去，按 **Raw**，全選複製）。
4. 回到主控台規則編輯框：**Ctrl+A 全選 → Ctrl+V 貼上**（整個換掉）。
5. 按 **Publish（發布）**。看到「已發布」就好，大約要等 1 分鐘生效。

---

## 第 4 步：新程式推上 main（要老師說可以才做）

1. 確認第 1～3 步都做完了。
2. 告訴 Claude（或維護的人）：「可以上了」。他會把開發分支 `claude/gracious-pasteur-773n2t` 合併到 `main`。
3. 等 GitHub Pages 更新（通常 1～3 分鐘）。用**無痕視窗**打開遊戲網址，右下角的版本要看到 **v3.14.0**。
4. 上了 main 之後，請 Claude 另外更新電腦教室入口頁的小訊息（`boyinslps/pcclass`）。

---

## 第 5 步：登入教師管理頁，做「一次搬移」

1. 打開 `teacher.html`（遊戲網址後面接 `/teacher.html`；舊控制台裡也有「🛠 新世界管理頁」按鈕）。
2. 用第 1 步的 email 和密碼登入。**只有自己的電腦才勾「記住這台電腦」**；在教室電腦不要勾。
   - 如果出現「這個帳號不是老師帳號」：回第 2 步檢查文件 ID 是不是和 UID 完全一樣。
3. 左邊選 **⚙ 設定**。
4. 找到 **「一次搬移（舊回報 → 抓蟲榜與信箱）」**。
5. 先按 **「先看會做什麼」**，看一下數字合不合理（幾位同學、幾個回報、要寄幾封信）。
6. 沒問題再按 **「執行搬移」**。
   - 這會用舊的「已確認回報」建立抓蟲榜分數；**還沒領過獎勵的同學**會收到信箱裡的獎勵信；領過的不會再發。
   - **不小心按兩次沒關係**，不會重複加分、不會多寄信。

---

## 第 6 步：補上「已經在遊戲外抓過 bug 的同學」

有些同學是用口頭、紙條或別的方式告訴你 bug（不是用遊戲裡的「回報問題」），這些不會在系統裡。用手動加分補上：

1. 左邊選 **🐛 回報與抓蟲榜**。
2. 按 **「＋ 手動加分」**（或在榜單那位同學的那一列按 **「加分」**）。
3. 用上面的搜尋框找到同學（可以打姓名、暱稱或座號），點選他。
4. 填分數（小問題 1、中 2、大 3，一次最多 20）、寫一句原因，按 **加分**。填負數是扣回加錯的分。
5. 加完到榜單看分數有沒有出現。

> 提醒：座號、姓名只在你自己的管理頁看，不要抄進文件或聊天裡。

## 第 7 步：提醒學生重新整理

- 上線時還開著遊戲的同學，**舊分頁要按 F5（重新整理）**，才會載到新版。
- 跟班上說一句就好：「遊戲更新了，請按 F5 重新整理。進新世界第一次要先取暱稱。」
- 如果有同學說「序號領不到、房間開不起來」，先請他按 F5。

## 萬一出問題，怎麼退回

**原則：先退規則，再退程式，兩個都退最安全。**

1. **貼回備份的舊規則**
   - Firebase 主控台 → Firestore Database → Rules。
   - Ctrl+A 全選，貼上第 3 步存的 `舊規則備份` 檔案內容，按 **Publish**。
2. **main 退回上一版**
   - 請 Claude（或維護的人）把 `main` 退回上線前的那一版（用 revert，不要刪歷史；上線前 main 是 v3.13.0）。
   - 等 1～3 分鐘，請學生按 F5。
3. 退回以後：
   - 學生已經存的資料**不會不見**（新世界存檔沒被動過）。
   - 已經寄出的信、抓蟲榜資料還留在資料庫，等下次再上線就接得上。
   - 老師帳號和 `mg_admins` 留著就好，不用刪。

**只有一部分壞掉怎麼辦？**
- 學生進不了遊戲／存不了檔：先退規則（第 1 項），學生按 F5。
- 只有教師頁壞掉：學生不受影響，不用退，告訴維護的人看錯誤訊息（畫面上的紅字）就好。
- 忘記密碼：Firebase 主控台 → Authentication → Users → 你的帳號 → Reset password。
